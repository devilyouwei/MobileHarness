# ADR0188: Main entry and specialist task ownership

Status: implemented; real-model/native-UI/physical-device acceptance pending.

Assistant is the default user entry and directly owns the 11 model-callable NexArm gesture/motor Actions as basic interaction. Photographer owns capture, photo understanding and disposition; Memory owns history workflows; ApplicationControl owns configuration, resources, navigation, Bluetooth connections and fixed settings device operations. Photographer retains only its code-owned photographic tracking Tool; ApplicationControl also registers the same general mechanical-arm Actions for Settings command tests. Action implementations and Agent registrations are many-to-many; role-local Action/Tool declarations follow the required execution semantics without forcing delegation for reuse. App grants Assistant the shared motor writer with joined takeover of Photographer. Streaming perception and synthesis retain their existing responsibilities.

At the Agent boundary, every input is a Signal and every business output is an Action; local frontend events need not cross that boundary. Delegation uses CommunicationAction with TaskRequest/Input/Progress/Result/Cancel, not a special handoff primitive. Results route to the runtime-captured executor; parent context receives explicit public reports only. Successful communication receipts acknowledge admission only and are record-only. Malformed preflight calls and rejected task admission provide bounded corrective model feedback; persistence/uncertain delivery errors after validation terminate without replay. New tasks use kind=request with authorized kind/target declarations; internal publication/speech grants do not enter the model task catalog. XML communication Action declarations are model-only adapters derived from JSON grants, never fake device function registrations. Model arguments cannot supply source, incarnation, trusted UI commands or execution ownership.

One reusable Agents/Support Chat worker executes one round and queues continuations. Role-specific builders, prompts, capabilities, task completion and independent durable context remain injected. Fixed backend requests from UI publish directly to their owning Agent and do not create delegated tasks or wait for a model worker. Local navigation, forms and rendering stay frontend-owned. Agent-issued UI effects remain callable and authorized; sharing UI methods does not require routing touch interaction through Assistant. Each model inbox is32 with one reserved continuation; output256; one model worker per role. Decisions retain4 requests,16 native calls,30 seconds cumulative execution and60 seconds queue wait. Existing task and communication bounds remain unchanged.

App owns stable interaction registration/output consumers separately from microphone generation. Microphone stop does not cancel business tasks. Playback grants validate actual producer and root/child task scope. Cancellation joins the real owner, and restart marks unfinished work interrupted without replay. Capture calls use the existing canonical Camera functions directly under Photographer, removing the Assistant-native-proxy-Photographer chain.

Questions are public structured progress, not private model history. Assistant selects one foreground interaction, forwards explicit task inputs, and rejects stale question/artifact references. Input production binds the interaction identity; ambiguity prompts clarification. Child responses retain real identity. History mutation retains existing UI confirmation and waits for the parent's committed decision/native-pair evidence; receipt acceptance is not such a barrier.

Migration must decode existing role context explicitly without a second writable store or resetting corrupt data. Existing Assistant history projection/import remains compatible. Existing deterministic workflows and native safety/resource algorithms are retained.

Validation: shared-worker synthetic ownership and protocol tests; all-role task routing and contexts; typed UI without models; microphone-independent lifetime; photo follow-up and stale references; confirmation/history barriers; cancellation, write failure and restart. Run scripts/check.sh and scripts/build-ios.sh, record simulator limitations and unsigned device build separately. Real models, native UI and physical acoustic/device acceptance remain pending.

Camera model operations are declared as seven scheduled Photographer Actions, sharing one Camera Channel and the canonical functions. Fixed single-command UI transactions retain private direct Tool grants for the same functions; these do not enter the model tool catalog. Successful camera preparation returns explicit acknowledged enabled/facing values. Child requests identify their active task separately from historical summaries; save/ignore questions use explicit progress with the captured artifact and keep the task open. Interaction scene transitions await root/child registration before lifecycle updates.


2026-10-10 implemented refinement: Assistant model calls are Action-only, including readEnvironment and authorized send. No runtimeInfo or native Agent.send is exposed. Parent evidence barriers apply to the committed Action/communication decision; existing native histories are preserved as inert text evidence. Shared Chat retains native-call support for explicitly registered business Tools; task send is Action-only across every role.


## Camera perception and model-visible state (2026-10-10)

✅ App publishes bounded camera.state facts from the actual CameraCoordinator state through InputGateway. Photographer subscribes only to phone.camera, fences the root session and revision, and atomically retains the latest snapshot while running or paused. Observation does not create a task, response or model request. Native execution results remain distinct owner-correlated Signals. Restart clears the prior live camera snapshot.

✅ A default-empty role context hook in shared Chat refreshes selected state before each provider request, including ReACT continuation, and stores the actual request evidence. Photographer projects existing persisted task/work/report/artifact state into its photography phase; no second writable task machine or role-specific mechanism enters Core/Chat. Camera facts are sampled every100ms while foreground and published only on change; Actions still validate actual readiness at execution time. UDP-like broadcast loss is not a synchronous guarantee of model knowledge. ❌ Live-provider and physical-camera acceptance remain pending.


2026-10-10 send audit: removed shared automatic native Agent.send declarations and the obsolete per-role exposure switch. The effective model catalog retains each role’s actual business Tools unchanged and adds only an authorized send Action for directed task grants. Explicit communication Tool registration fails configuration assembly. All framework-originated communication still uses CommunicationAction; admission receipts and TaskResult remain separate.
