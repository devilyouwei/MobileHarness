# ADR 0125: Bounded Bluetooth exception recovery and diagnostics

Status: Accepted. Supersedes App's one-attempt/manual-only feedback recovery contract; ADR0123 transport pacing remains in force.

Current scene/retry contract: [ADR0142](0142-bluetooth-scene-lifetime-and-retry-episodes.md) supersedes the stable-connection budget refill and unconditional background disconnect described below. Connection success clears attempts immediately; eligible foreground return starts a new episode while healthy links are retained during joined control suspension.

## Decision and ownership

AppBluetoothWorkflow owns one recovery state machine and one bounded process-local diagnostic cache. PlatformKit supplies native power/phase, monotonic snapshot revisions, query quarantine and traffic facts; Actions owns physical behavior/completion, and UI receives presentation values only. BluetoothRecovery.swift owns retry classification, 1/2/4-second backoff, three-attempt cap, cooperative two-minute active-worker deadlines.

Actual native loss, sustained SDK-blocked sending and quarantined queries enter native cleanup even when the radio remains connected. Feedback silence only creates a diagnostic under ADR0130. Clean up connection generation, pending settings requests, motor inputs/aim, connection/manual/live workers, native session, controller, mapping/planner and stale telemetry. Agent finite Actions and Channel queues remain owned by execution Runtime under ADR0129. Confirm native disconnect before creating another connection. Ordinary invocation/target completion failures do not imply transport loss. Firmware/service and storage/configuration failures during connection setup stop retries. Native protocol errors close the damaged link and follow bounded recovery; business pose/completion failures do not initiate recovery.

Automatic/manual reconnect completes on native subscription, without an active state/version/IK probe, gesture, home movement or replay (ADR0130). Short-lived successful links retain the consumed attempt budget; 30 seconds of native connectivity resets it on the next failure. Foreground/power resumption preserves attempts but starts a fresh active time window. Terminal failure/exhaustion requires manual retry. User disconnect/forget disables and persists automatic reconnect preference; background suspends recovery, and page disappearance does not own it. Cleanup must join even if a dependency ignores cancellation; deadlines never grant a second owner over unfinished cleanup or imply physical stop.

The memory cache holds four most recently used devices and 32 newest events each. Event text/details have fixed bounds. Device details show recovery state/attempts and retry/cancel controls under 当前状态. A compact 异常与恢复记录 entry opens a native sheet with expandable events and explicit clear; post-connection errors have no duplicate inline row. Opening/dismissing that UI sheet does not change connection or execution policy. Native events retain their original time/category/reason/connection and traffic facts. App recovery events alone carry episode/cause/attempt/elapsed metadata; connection/lifecycle events and history-gap markers have separate categories (ADR0131). No payload/media or persistent history is introduced.

## Validation and limits

Simulation tests exercise loss/blockage/quarantine, duplicate/obsolete events, radio changes, manual cancellation, retry exhaustion, cleanup failure and cache eviction. Repository checks and available builds are required; physical radio/device/firmware and native layout validation remain pending. A responsive official vendor app does not prove receipt of feedback required by this control contract. True device failure may require user-side device restart after the bounded recovery stops.

2026-10-04 validation: all 55 Bluetooth simulations pass, including active-aim cleanup/new-input admission and terminal-failure radio changes. Boundary checks, Swift formatting, available package build, UI syntax parsing and project/privacy/entitlement plist validation pass. `scripts/check.sh` remains unsuccessful on two pre-existing aim-planner tests; one vision time-limit failure in the final full run passed in isolated rerun. The initial `scripts/build-ios.sh` invocation could not use Xcode because Command Line Tools were selected. Full Xcode 27.0 was subsequently located and selected per command; the signed native build and installation are recorded in [Validation-History](../Validation-History.md). No physical-device validation was performed.

Recovery scope refinement: [ADR0129](0129-bluetooth-session-isolation.md) removes global voice quiescence and recovery-driven Action cancellation/admission suspension. Native session closure fails operations through normal results; accepted Channel queues remain intact. [ADR0130](0130-passive-ble-manual-control.md) supersedes active connection verification and feedback-silence reconnect policy for the current App BLE connection.


[ADR0131](0131-independent-bluetooth-diagnostics.md) implements independent native SDK fault types/messages and App recovery records; Action/Tool resource, business and completion errors do not enter device history or trigger recovery. ADR0129 independently isolates Agent scheduling/session lifetime.
