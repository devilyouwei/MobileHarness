# 0058 — Replace default Kokoro with MOSS-TTS-Nano

Date: 2026-09-28. Supersedes ADR 0052's default synthesis and resource selection.

The user repeatedly reproduced a process crash on iPhone 17 Pro / iOS 27 before Kokoro speech began and explicitly requested MOSS-TTS-Nano Core ML. A Swift error fallback cannot recover a process abort. Remove Kokoro from production registration and packaged TTS resources; keep its isolated comparison code/tests without exposing an App fallback.

ModelKitDefaults registers ModelID("moss-tts-nano") as the only synthesis default. ModelKitMossNano owns request/session admission, bounded mono PCM and the managed resource. ModelKitMossCoreML contains the graph loop and text processing adapted from FluidAudio PR #917 at abbde6b9b80c0e7c2c488f35b0b225c0e8cab08f. The public high-level manager was unsuitable: it downloads resources and uses an unbounded stream. Copy only the relevant licensed implementation, retain attribution, and add synchronous throwing emission, per-graph cancellation, per-frame autorelease cleanup and explicit failure on missing stop token. Existing FluidAudio dependency is not updated; no new package is introduced.

Pin model resources to 408475d01c46c9290b6546edf31e9cc5cbb202cd from FluidInference/moss-tts-nano-coreml. Package the four compiled streaming graphs, local tokenizer/config and zh_1/en_2 reference codes. Do not package voice-registration or batch-decoder graphs. CPU+GPU is explicit for all graphs; no speculative ANE fallback. Native 48 kHz stereo is downmixed to mono for the existing cache/playback path. Resource ownership and Agent JSON registrations do not change.

The capability has one worker, a 256-event bounded failure-on-overflow stream, 2048 UTF-8 input bytes and 60-second total output limit. Backend chunks remain bounded, including sampling state and KV caches. Exact contracts live in the backend and adapter READMEs. Following reported cache overflow and the user’s request to enlarge it, StorageAudio defaults to 8 MiB live PCM per handle, matching the synthesis Agent’s per-request output limit (about 43.7 seconds at 48 kHz mono Float32). With 32 handles the aggregate PCM ceiling is 256 MiB, allocated on demand. The 2048-frame cap, explicit overflow failure and three-second empty-read timeout remain unchanged. This is a bounded capacity increase, not producer backpressure.

MossValidation replaces the Kokoro diagnostic scheme and reports 48 kHz timing/playback. MOSS is a beta real model; graph conversion and source are experimental. Chinese number/date normalization is not yet ported. Run repository checks, all simulator builds and opt-in Mac synthesis before reporting results. Builds or Mac output do not establish iPhone safety, performance or audio quality. See ../Moss-Validation.md.

Device validation exposed 10.63 s first-prediction latency after graph loading, exceeding the three-second playback wait. Defaults supplies a real synthesis warmup closure; App invokes it before enabling conversation and diagnostic timing. It drains synthetic Chinese PCM without playback. Keep the existing playback timeout; do not hide initialization latency inside the first user reply.
