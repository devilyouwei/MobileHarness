# 摄影构图与运镜需求

状态：❌ 自主构图与运镜策略待实现。本文件只保留未完成需求；已有姿态订阅、相机操作与 NexArm 瞄准能力以 [Photographer 当前设计](../../MobileHarness/Agents/Photographer/README.md) 和 [ADR0102](../adr/0102-photographer-aim.md) 为准。

## 产品目标

用户通过摄影任务指定主体和意图，系统结合共享视觉感知选择构图、跟随方式及相机运动，形成可追溯的摄影产物。构图策略与持续跟踪体验仍需明确任务范围、完成标准及用户停止/接管方式。

## 技术接入要求

- 摄影业务拥有者消费 VisionPerception 发布的共享观测，不拥有 YOLO 推理或骨架 UI，也不直接读取其他 Agent 内部状态。数据字段、容量和新鲜度见 [感知输入输出契约](../../MobileHarness/Agents/VisionPerception/README.md#输入订阅与输出契约)。
- 按实际业务补充用户意图、设备反馈和必要的发布/定向消息契约；沿用当前已声明的输入、权限与固定调用，不将旧提案中的缺失协议描述当成当前事实。
- 明确构图算法、运动限制、目标与实测位置的区别，以及设备故障、失联和停止确认语义。发送或接纳指令不等于物理到位，断连恢复不自动重放业务动作。
- 接受最新观测可能跳帧、无人或过期；没有真实来源时不推断 tracking ID、深度、机器人状态或到位事实。手机视觉刷新不提供硬实时保证。
- 持续控制由明确的根级所有者持有，定义容量、覆盖/拒绝、取消、清理和结束条件；物理安全不能依赖 UI 页面或 iOS 后台持续执行。
