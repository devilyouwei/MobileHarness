# Assistant 聊天首页与眼睛形态

2026-11-26 记录，待实现。

## 用户体验

- 主交互提供常规聊天形态，以可滚动的会话记录区和固定可用的输入区组织页面。用户与 Assistant 的消息按时间排列、角色清晰可辨，用户可以往上查看当前会话的历史上下文。
- 用户可以用键盘输入并发送消息，也可以继续口述。两种输入进入同一个 Assistant 会话，后续回复沿用已有上下文。语音输入显示识别终稿，Assistant 回复显示可阅读的文本。
- 保留现有机器人眼睛（Face）形态，用户可以在聊天与 Face 之间切换。切换沿用同一个会话，聊天历史、尚未发送的草稿和在途回复状态随会话保留。两种形态的具体入口和布局在交互设计时确定。

## 现状与衔接

首页已有 Face、实时字幕和类型化文字提交端口。设置页已有 Assistant 历史记录入口。本需求把文字输入和可连续阅读的对话带到主交互，复用现有输入与会话记录能力。新增输入框仅提交用户消息，AI 主动提供交互界面时遵守[用户导航与 AI 交互边界](../Manual-Navigation-and-Agent-Interaction.md)。[当前首页契约](../../../MobileHarness/UI/Conversation/README.md) · [当前导航与历史入口](../../../MobileHarness/UI/Root/README.md)

## 验收条件

- 从首页用键盘发送一条消息，再用语音追问。聊天记录按顺序显示双方消息，回复能接续上一轮内容。
- 查看较早的消息后返回最新位置，核对当前会话和发送入口仍可用。
- 分别在有未发送草稿和有在途回复时往返聊天与 Face。草稿保留，回复继续归属原会话，每条用户消息只提交一次。
