# 用户相册与记忆需求计划

记录日期：2026-10-15；需求补充：2026-10-25。状态：✅ 基础照片相册已实现；❌ 真机验收、扩展影像能力与语义记忆待完成。

在设置的“用户”板块中，与现有“Agent 记录”并列增加“相册”和“记忆”两个入口，各自进入独立页面。相册沉淀用户摄影任务的媒体产物；记忆以日记式时间线沉淀对话内容，并定期增量整理。两者作为新增产品需求，与 [核心架构技术需求](../technical/Core-Architecture-Improvement-Plan.md) 分开跟踪。

## 页面与信息层级

| 用户板块入口 | 页面内容 | 状态 |
| --- | --- | --- |
| 记忆 | 按时间组织的日记式记忆条目，可查看摘要、关键词及原始对话来源。 | ✅ 静态条目；❌ 页面与跳转待实现。 |
| 相册 | 用户在 Photography Tasks 中产生的图片、视频等媒体，按时间浏览并查看产物详情。 | ✅ 基础照片页面与导航；❌ 视频／分析／搜索待实现。 |
| Agent 记录 | 按 Agent 查看原始记录；当前提供 Assistant 聊天记录及 Task 来源。 | ✅ 已有入口及导航。 |

相册和记忆不放进某个 Agent 的记录子页面。点击入口与页面跳转直接使用 UI 导航；打开页面不触发媒体生成或记忆重算。页面只消费展示值，业务读取与更新通过注入接口交给所属服务。

## 1. 用户相册

收录用户 Photography Tasks 的媒体产物，保留原始图片、视频及必要元数据。按拍摄/产生时间组织列表，支持图片查看、视频播放和来源追溯；拍摄时间与入库时间分别保存。相册是 App 内的用户产物页面，导出到系统照片库属于独立操作。

- 每个产物保留稳定媒体 ID、媒体类型、原文件引用、产生时间及真实存在的 Task、对话/消息来源关联。Task 关联表示产物来源，不新增“必须启动 Task 才能调用相机”的限制。
- 区分文件写入中、已就绪、失败与不可用状态；Task 部分失败不抹去此前真实产出的媒体，Task 成功也不代替文件已就绪的确认。
- 相册长期保留策略与模型输入/临时预览缓存分开。已收录作品不能因会话结束、页面关闭或临时缓存 FIFO 回收而被静默删除；容量不足和文件缺失必须明确展示。
- 实施前明确临时预览、忽略、收录、导出及删除的关系，以及容量/保留策略。本期 `savePhoto` 明确改为收录 App 相册；`ignorePhoto` 仍仅忽略当前预览，系统 Photos 导出移至相册详情。
- 图片与视频属于同一产品需求；视频录制、编码、缩略图、播放和存储接口仍需实现，不能将现有 JPEG 流程视为已支持视频。

✅ 已有 JPEG 产出、媒体记录和历史图片读取基础，现已补齐基础照片相册页面、显式收录、导入、单张导出与删除。❌ 视频、分析、语义搜索、完整摄影任务聚合及原生真机验收仍待完成。现有缓存生命周期见 [Storage Media](../../../MobileHarness/Storage/Database/Media/README.md)。

验收：仅展示真实来源的产物，按时间分页浏览，重启后保留，图片/视频正确读取，来源可追溯；覆盖部分失败、容量不足、文件缺失及页面离开后的任务收尾。

## 2. 用户记忆

以已持久化的原始对话为依据，周期性增量生成和修订日记式记忆，按所覆盖的内容时间组织。每条记忆包括以下信息：

| 内容 | 需求 |
| --- | --- |
| 时间 | 覆盖的开始/结束时间；生成、更新时间和修订版本分别记录，重算不改变原始内容的时间归属。 |
| 摘要 | 对该时间段内对话、经历和关键事件的概括；区分原始事实与模型归纳，保留来源可追溯性。 |
| 关键词 | 与摘要及来源对应的检索词，随内容修订同步更新。 |
| Embedding | 用于语义检索的向量及其模型标识、维度、版本和内容版本关联；更换模型或修改内容后需要对应重建。 |
| 原始对话索引 | 精确指向稳定的对话 ID、消息/请求 ID 或明确范围，必要时关联 Task；不只保存标题、列表位置或压缩摘要。 |

用户页面展示时间线、摘要、关键词及来源入口；embedding 属于底层检索数据，无需默认展示原始向量。原始对话记录、Task 上下文压缩与用户记忆各自保留职责，生成记忆不覆盖原始证据。来源读取或摘要/向量生成失败时明确保留失败或待更新状态，不发布虚构完成结果。

### 定期迭代与生命周期

- 更新由业务拥有者根据新增或变化的持久化对话增量推进；记录已处理范围与来源版本，避免重复条目，修订已有记忆时保留来源关联。没有新内容时不无意义地重算。
- “每过一段时间”作为可配置周期需求记录；具体间隔、条目时间粒度、覆盖窗口和单次预算待实施前确定，不默认固定为每日。
- 更新任务由 App 根生命周期管理的服务承载，Memory 业务拥有者决定整理策略，离开页面不取消已接纳工作。iOS 后台执行机会有限，允许到期标记并在下次可运行时补做，不承诺固定时刻后台常驻执行。
- 定义单次读取、模型输入、待处理任务和并发的上限，以及取消、失败重试和重启恢复语义。新版本达到发布条件后再替换当前可用版本，避免摘要、关键词和向量版本混用。
- 原始对话删除或修订时，按明确策略失效、重算或删除关联记忆和向量；来源不可用必须如实呈现。具体用户删除/保留策略在实施前细化。

✅ 当前 Memory Agent 负责历史事务和标题生成。❌ 日记式记忆抽取、周期迭代、embedding 生成/存储/检索及记忆页面尚未实现；当前 ModelKit 也未提供生产 embedding 能力。参见 [Memory 当前职责](../../../MobileHarness/Agents/Memory/README.md) 和 [ModelKit 能力边界](../../../MobileHarness/ModelKit/README.md)。

验收：按覆盖时间呈现，定期增量更新且不重复，修订后摘要/关键词/向量一致，来源精确跳转，删除或变更后索引同步处理；覆盖空窗口、模型/存储失败、取消、重启和错过周期后的补做。

## 模块衔接与实施前细化

UI 拥有两个独立页面及展示契约；摄影业务拥有者负责媒体产物归属，Memory 业务拥有者负责记忆整理与更新策略；Actions 提供需要对外执行的业务操作。ModelKit 提供注入的摘要与 embedding 能力，PlatformKit 提供原生媒体能力；Storage 提供媒体、记忆、向量及来源索引的存取契约，不执行模型归纳。App 负责服务装配、生命周期和模块接口桥接。

沿用已拆分的 Storage 接口与后端；新增记录、查询和索引需先设计契约、迁移和容量边界，不默认引入向量数据库或第三方依赖。当前仅记录需求，不创建源码目录、模块或运行时定时任务。实施前先更新整体设计和各受影响目录 README；代码检查、模型结果、原生 UI 与物理设备验收分别记录。


## 3. 扩展范围：摄影组件、影像理解与自然语言检索

以下记录 2026-10-25 的新增产品目标。基础照片相册交付见末节；其余扩展为 ❌ 待实施，候选接口和分期不代表已定技术契约。既有设置入口作为相册／记忆的浏览入口保留；摄影等小功能采用首页覆盖组件的方向，不要求每项功能打开独立页面。

### 摄影 Actions 与 Skill

- 用户通过自然语言，由 LLM 加载 Skill 并选择 Actions，覆盖倒计时拍照、拍摄参数／模式选择、开始录像、结束录像。摄影 UI 提供独立组件，展示真实预览、模式、倒计时、录制状态和产物。
- 当前可复用 Camera.Capture 的 open、close、flip、retry、takePhoto、savePhoto、ignorePhoto。Assistant 的 Photography Skill 已直接调用这些函数；Photographer 当前是确定性 UI／跟踪角色，不是独立摄影 LLM。新能力优先延续既有调用链，不默认增加 Agent 或模块。
- 候选操作包括能力查询、配置拍摄、倒计时拍摄及取消、开始／结束录制、录制状态查询。最终函数命名、粒度和通道划分需设计后确定；实际计时、录制和文件收尾由执行拥有者完成，不能依赖模型等待或页面存活。
- “iOS 支持的各种模式”需形成公开 API、系统版本、设备／镜头、格式和组合限制的能力矩阵。普通照片／录像与闪光灯、变焦、对焦、曝光、分辨率／帧率优先梳理；Live Photo、RAW／ProRAW、深度、人像相关输出、慢动作、延时与电影效果等逐项调查，不承诺复刻系统相机所有模式。
- 录制开始回执只代表实际开始；停止需等待编码与文件关闭，再发布 ready 媒体。定义 recordingID、重复停止、最长时长／容量、取消、前后台、中断、崩溃恢复及部分文件处理。停止／取消必须能在长工作期间被接纳，不能被同通道等待阻塞。
- 录像音轨需协调现有麦克风、持续聆听、ASR 和播放的资源所有权，明确无麦克风权限时是否允许用户选择无声录像，不静默降级。

### 首页组件窗口方向

- 摄影先形成可嵌入首页覆盖层、可复用的组件边界；未来小游戏、画板等共用窗口宿主。窗口的最小化、关闭、最大化全屏、多窗口层级与布局先记录，完整桌面交互后续实施。
- 候选窗口状态：组件实例 ID、类型、展示状态和焦点／层级；UI 负责布局、命中、呈现与回执。组件业务状态和长工作由各自业务拥有者管理，不放进通用窗口管理器。
- 最小化不等于停止录像；关闭录制组件时的停止／保留行为需明确，不能靠 View 消失隐式取消。后台捕获按原生能力和既有生命周期约束处理，不因最小化而承诺后台运行。
- 现有相机依赖首页路由／前台准入，照片查看采用保留下层挂载的全屏覆盖；它们可供迁移参考，但不等于已实现通用窗口系统。实施前修订相机可见性与捕获生命周期的耦合。
- 当前 UI/Components 是底层原生视觉组件目录，不等同于产品窗口框架；先在已有目录职责内设计，不在本轮创建新目录或模块。

窗口与岛的进一步组件契约、相机准入迁移、Action 候选接口和首期顺序统一见 [Face 窗口与 App 内灵动岛规划](../Face-Window-Island-Plan.md)。该专项记录用户确认的 App 内岛范围；本文继续维护摄影／相册／分析／记忆需求，不将窗口计划视为已实现。

### 相册、分析与记忆的分层

- 相册记录真实媒体及资源：照片、视频，以及 Live Photo 等可能包含多个文件的复合产物；稳定媒体 ID 与文件资源 ID 分开考虑。原片、缩略图、分析输入和导出副本拥有不同生命周期。
- 影像分析独立保存描述、标签、评分、来源片段／时间范围、模型／提示版本、内容版本和处理状态。原生元数据、模型推断、用户修正分别记录；模型标签不能冒充真实地点、人物身份或家庭关系。
- 评分维度待讨论，例如技术质量、构图或用户偏好；不以单一不透明分数代替所有维度。视频需要有界抽帧／片段分析和时间范围证据，不能用一张封面代表整段内容。
- 记忆使用独立表／仓库，影像是来源之一，聊天记录也是后续来源。媒体分析并不自动等于用户记忆；建立 sourceType、稳定来源 ID、来源版本及视频片段范围等关联候选。完整记忆抽取、合并、冲突与遗忘策略留待专门讨论。
- 建议将自动收录 App 拍摄产物与用户明确保留策略作为首批讨论重点。原需求以摄影产物为范围；是否导入／索引系统照片库尚未确定。当前 Photos 仅有 add-only 写入，不能当作已有系统相册读取能力。
- 当前 CapturedPhotoStore 使用 1024 张／2 GiB、evictOldest 的有界照片策略；长期相册不能直接继承该自动淘汰策略。已有媒体记录是基础，不是完整相册 schema；需设计分页、媒体时间、资源关联、任务／消息来源和数据库迁移。
- 定义删除对原片、分析、检索索引和派生记忆的传播，以及 App 相册与系统 Photos 副本的关系。分析失败不阻止查看已就绪原片；原片失败不得发布成功相册项。

### 自然语言相册搜索

目标示例：“帮我找找在公园遛娃的视频”“我家小狗的照片，这周内拍的”。检索须 Action 化并配合 UI 结果组件，支持缩略图、筛选条件、详情／播放和视频匹配片段。

建议链路：LLM／Skill 解析意图 → Action 校验结构化查询 → 时间／类型等确定性过滤 → 文本／标签与语义召回 → 有界重排 → UI 结果呈现。查询、翻页、详情／播放、结果呈现按职责拆分；模型只拿有界摘要和媒体 ID，不在提示中装载整个相册。

- 时间解析记录参考时刻、用户时区、周起始规则及明确起止边界；“这周”不能简化为过去七天。
- “公园”“遛娃”需要场景／活动语义；“我家小狗”还涉及用户确认的主体关联。没有身份依据时只返回候选或澄清，不把视觉相似当作用户归属事实。
- 向量能力尚未实现。先设计文本检索／结构化过滤及语义索引接口，再依据真实模型效果决定 embedding 与向量后端；不默认引入第三方向量数据库。缺失索引／分析失败时展示覆盖范围，空结果不等于媒体一定不存在。
- 结果附可解释的匹配依据及必要的视频时间范围；索引更新、内容修订和删除传播受版本约束，避免旧索引召回已删除或不可访问的文件。

### 建议实施顺序与验收重点

1. 确认媒体来源、收录／保存／删除语义、模式能力矩阵、录像与音频资源策略；设计媒体资源与独立影像来源记忆契约。
2. 摄影组件边界＋基础录像／倒计时 Actions＋长期相册存储，闭环验证拍摄、停止收尾、重启后浏览／播放。
3. 异步分析、标签和分维度评分；定义队列容量／溢出、并发、模型预算、重试及重启补做，离开组件不丢失工作。
4. 自然语言检索 Actions／Skill 与结果 UI，验证中文语义、时间边界、视频片段、空结果和分析覆盖不足。
5. 后续展开完整窗口管理和多来源记忆体系；本期先保留必要边界，避免业务状态绑定窗口。

每期分别记录自动化／构建、真实模型效果和原生真机验收；本轮未运行代码检查或 iOS 构建，也不构成任何功能验收。

## 基础相册首期实施

✅ 基础功能已实现，真机验收待完成：仅照片，现有savePhoto收录App相册；设置相册入口提供浏览、导入、缩放详情、导出至手机及确认删除。导入保留JPEG／HEIC／PNG文件，不重压缩；Live Photo仅静态图。每批20张、单张32MiB／100百万像素、分页40、总1024项／2GiB，已收录作品禁止自动淘汰。原片／收录记录／历史来源生命周期分别管理；旧媒体不自动收录。系统Photos独立副本不联动删除。分析、语义搜索、视频和记忆生成不在本期。
