# 用户相册与记忆需求计划

记录日期：2026-10-15。状态：❌ 两项均待实施。

在设置的“用户”板块中，与现有“Agent 记录”并列增加“相册”和“记忆”两个入口，各自进入独立页面。相册沉淀用户摄影任务的媒体产物；记忆以日记式时间线沉淀对话内容，并定期增量整理。两者作为新增产品需求，与 [核心架构技术需求](../technical/Core-Architecture-Improvement-Plan.md) 分开跟踪。

## 页面与信息层级

| 用户板块入口 | 页面内容 | 状态 |
| --- | --- | --- |
| Agent 记录 | 按 Agent 查看原始记录；当前提供 Assistant 聊天记录及 Task 来源。 | ✅ 已有入口。 |
| 相册 | 用户在 Photography Tasks 中产生的图片、视频等媒体，按时间浏览并查看产物详情。 | ❌ 新增独立页面。 |
| 记忆 | 按时间组织的日记式记忆条目，可查看摘要、关键词及原始对话来源。 | ❌ 新增独立页面。 |

相册和记忆不放进某个 Agent 的记录子页面。点击入口与页面跳转直接使用 UI 导航；打开页面不触发媒体生成或记忆重算。页面只消费展示值，业务读取与更新通过注入接口交给所属服务。

## 1. 用户相册

收录用户 Photography Tasks 的媒体产物，保留原始图片、视频及必要元数据。按拍摄/产生时间组织列表，支持图片查看、视频播放和来源追溯；拍摄时间与入库时间分别保存。相册是 App 内的用户产物页面，导出到系统照片库属于独立操作。

- 每个产物保留稳定媒体 ID、媒体类型、原文件引用、产生时间及真实存在的 Task、对话/消息来源关联。Task 关联表示产物来源，不新增“必须启动 Task 才能调用相机”的限制。
- 区分文件写入中、已就绪、失败与不可用状态；Task 部分失败不抹去此前真实产出的媒体，Task 成功也不代替文件已就绪的确认。
- 相册长期保留策略与模型输入/临时预览缓存分开。已收录作品不能因会话结束、页面关闭或临时缓存 FIFO 回收而被静默删除；容量不足和文件缺失必须明确展示。
- 实施前明确临时预览、忽略、收录、导出及删除的关系，以及容量/保留策略。既有 `savePhoto` / `ignorePhoto` 语义不因本需求记录而改变。
- 图片与视频属于同一产品需求；视频录制、编码、缩略图、播放和存储接口仍需实现，不能将现有 JPEG 流程视为已支持视频。

✅ 当前已有 JPEG 产出、媒体记录和历史图片读取基础。❌ 用户相册页面、摄影任务产物聚合和视频完整链路待实施。现有缓存生命周期见 [Storage Media](../../../MobileHarness/Storage/Database/Media/README.md)。

验收：仅展示真实来源的产物，按时间分页浏览，重启后保留，图片/视频正确读取，来源可追溯；覆盖部分失败、容量不足、文件缺失及页面离开后的任务收尾。

## 2. 用户记忆

以已持久化的原始对话为依据，周期性增量生成和修订日记式记忆，按所覆盖的内容时间组织。每条记忆包括以下信息：

| 内容 | 需求 |
| --- | --- |
| 时间 | 覆盖的开始/结束时间；生成、更新时间和修订版本分别记录，重算不改变原始内容的时间归属。 |
| 摘要 | 对该时间段内对话、经历和关键事件的概括；区分原始事实与模型归纳，保留来源可追溯性。 |
| 关键词 | 与摘要及来源对应的检索词，随内容修订同步更新。 |
| Embedding | 用于语义检索的向量及其模型标识、维度、版本和内容版本关联；更换模型或修改内容后需要对应重建。 |
| 原始对话索引 | 精确指向稳定的对话 ID、消息/请求 ID 或明确范围，必要时关联 Task；不只保存标题、列表位置或压缩摘要。 |

用户页面展示时间线、摘要、关键词及来源入口；embedding 属于底层检索数据，无需默认展示原始向量。原始对话记录、Task 上下文压缩与用户记忆各自保留职责，生成记忆不覆盖原始证据。来源读取或摘要/向量生成失败时明确保留失败或待更新状态，不发布虚构完成结果。

### 定期迭代与生命周期

- 更新由业务拥有者根据新增或变化的持久化对话增量推进；记录已处理范围与来源版本，避免重复条目，修订已有记忆时保留来源关联。没有新内容时不无意义地重算。
- “每过一段时间”作为可配置周期需求记录；具体间隔、条目时间粒度、覆盖窗口和单次预算待实施前确定，不默认固定为每日。
- 更新任务由 App 根生命周期管理的服务承载，Memory 业务拥有者决定整理策略，离开页面不取消已接纳工作。iOS 后台执行机会有限，允许到期标记并在下次可运行时补做，不承诺固定时刻后台常驻执行。
- 定义单次读取、模型输入、待处理任务和并发的上限，以及取消、失败重试和重启恢复语义。新版本达到发布条件后再替换当前可用版本，避免摘要、关键词和向量版本混用。
- 原始对话删除或修订时，按明确策略失效、重算或删除关联记忆和向量；来源不可用必须如实呈现。具体用户删除/保留策略在实施前细化。

✅ 当前 Memory Agent 负责历史事务和标题生成。❌ 日记式记忆抽取、周期迭代、embedding 生成/存储/检索及记忆页面尚未实现；当前 ModelKit 也未提供生产 embedding 能力。参见 [Memory 当前职责](../../../MobileHarness/Agents/Memory/README.md) 和 [ModelKit 能力边界](../../../MobileHarness/ModelKit/README.md)。

验收：按覆盖时间呈现，定期增量更新且不重复，修订后摘要/关键词/向量一致，来源精确跳转，删除或变更后索引同步处理；覆盖空窗口、模型/存储失败、取消、重启和错过周期后的补做。

## 模块衔接与实施前细化

UI 拥有两个独立页面及展示契约；摄影业务拥有者负责媒体产物归属，Memory 业务拥有者负责记忆整理与更新策略；Actions 提供需要对外执行的业务操作。ModelKit 提供注入的摘要与 embedding 能力，PlatformKit 提供原生媒体能力；Storage 提供媒体、记忆、向量及来源索引的存取契约，不执行模型归纳。App 负责服务装配、生命周期和模块接口桥接。

沿用已拆分的 Storage 接口与后端；新增记录、查询和索引需先设计契约、迁移和容量边界，不默认引入向量数据库或第三方依赖。当前仅记录需求，不创建源码目录、模块或运行时定时任务。实施前先更新整体设计和各受影响目录 README；代码检查、模型结果、原生 UI 与物理设备验收分别记录。
