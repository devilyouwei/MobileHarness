# 录制 Assistant 的名字作为唤醒词

2026-11-26 记录，待实现。

## 在声音设置中录制唤醒词

在「设置 → 语音 → 关键词检测」的 Zipformer 配置下提供独立的「唤醒词」开关。首次开启时弹出录音引导，请用户用自然语速分段说出同一个名字。唤醒词通过录音注册，注册过程全程无需手输名字或语音转写。首版需要三段有效录音，界面显示录制进度，并允许单独重录有明显噪声、削波、漏录或疑似与其他样本不一致的一段。边界和一致性检查根据录音质量及声学特征给出重录提示。

三段通过后，用同一个 Zipformer 编码器提取逐帧特征。将模板及其模型和特征版本保存在本地，保存成功后开启唤醒词，重启后恢复已保存配置。设置中可关闭、重新录制或删除。重录成功后整组替换，取消或失败时保留上一次保存的配置。Zipformer 不可用时，明确显示原因，待其就绪后才能录制或检测。录音只用于本地提取特征，完成或取消后释放录音数据。

## 在 quiet 模式下唤醒

开启唤醒词后，SpeechPerception 在 `quiet` 中对实时麦克风音频复用现有 16 kHz 预处理和 Zipformer 流式编码器。首版候选算法用逐帧余弦距离和子序列动态时间规整（DTW）将有限长度的音频特征与各录音模板对齐，允许语速变化。使用归一化匹配分，完整名字与任一有效模板匹配且分数高于唤醒阈值，即可发布一次唤醒信号。分数是相似度，阈值用整组模板取最高分后的结果独立校准。比对从编码器输出完成，无需调用关键词 decoder、joiner 或等待 ASR。

唤醒取决于是否说出了注册的名字。不同说话人喊出同一个名字都属于有效唤醒，验证覆盖不同语速、口音和距离。其他名字、近音词和未说出完整名字的片段属于负样本。唤醒模板和门限独立于已有的快停词表与快停置信度设置。

Assistant 收到当前 `quiet` 会话的有效唤醒信号后，通过现有 `listening` 状态入口退出 `quiet`，目标明确为全双工 `full`。即使进入 `quiet` 前处于半双工 `half`，名字唤醒也以 `full` 为目标，并遵循现有全双工能力校验。[Assistant 聆听状态契约](../../../MobileHarness/Agents/Assistant/Input/README.md#listening-and-quiet)

## 方案依据与验证重点

多次录入是已有的产品做法。Sensory 的自定义触发词通常录四次，交互式工具会对不可用录音要求重录。DONUT 的研究方案用三段录音学习唤醒短语。三段是本项目首版的录入门槛，后续可对照更多样本的收益。[Sensory 唤醒词录入指南](https://doc.sensory.com/tnl/7.9/getting-started/#wake-word-enrollment) · [DONUT 论文](https://openreview.net/pdf?id=SkMRja6ssQ)

公开实现已有用冻结语音编码器加子序列 DTW 检测自定义唤醒词的例子。项目优先验证现有 Zipformer 编码器的表现。任一模板过阈值有利于接纳不同读法，也会增加碰巧匹配某段的机会，因此要用整组模板测阈值，并报告漏唤醒率、每小时误唤醒次数及端到端唤醒延迟。验收样本与录入样本分开，包含不同人说同名、不同名字、近音词、电视或背景对话，以及真机麦克风条件。[Jarvis 模板匹配实现](https://github.com/LokalOptima/jarvis) · [Apple 唤醒词误触发评估](https://machinelearning.apple.com/research/hey-siri)

## 验收条件

- 首次打开开关时进入录音引导，达到三段有效录音并保存后启用。录音可单段重录，重启后可使用已保存的模板。关闭、取消重录、保存失败和模型不可用时，界面与实际检测状态一致。
- 在支持全双工的采集环境中，从 `half` 进入 `quiet`。由未参与录入的人以不同语速喊出同一个名字，其中任一模板过阈值即可触发一次唤醒，Assistant 无需 ASR 最终结果即可进入 `full`。
- 录入「贾维斯」后，监听到「约翰」、近音词或只说了名字的一部分时，唤醒词路径不触发。用连续背景音频和独立正反例校准和验证唤醒门限。

## 未来设想：将 listening 简化为两态

后续可评估移除半双工 `half`，把 `listening` 简化为布尔值。`true` 表示已唤醒，按全双工模式聆听。`false` 表示安静模式，保留用于检测预设名字的音频输入。用户喊出预设名字并匹配成功时，`listening` 从 `false` 切换为 `true`。

现有聆听逻辑在音频采集不支持回声消除时会退回半双工。实施两态设计前，需要明确这类设备或音频路由上的行为。[现有聆听状态契约](../../../MobileHarness/Agents/Assistant/Input/README.md#listening-and-quiet)
