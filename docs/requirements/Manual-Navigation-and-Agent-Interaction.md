# 用户导航与 AI 交互边界

2026-11-26 记录，待实施。

## 产品规则

- App 的页面导航由用户手动点击、返回手势或等效的无障碍操作触发。设置、相册、历史及详情等现有页面由 UI 自己维护导航路径。
- AI 主动交付用户可感知的交互有两种形式。无需界面时直接口述。需要展示内容、收集输入或确认时，用现有 Window 组件打开专用窗口，交互发生在该窗口内。
- 禁止笔记所称的 Avedit，也就是 AI 直接编辑或操控现有页面元素。AI 与 Agent 禁止通过 Action、Tool 或其他路由替用户进入或返回页面、点击控件、填写表单或修改现有页面的交互状态。专用窗口通过明确的业务接口展示内容和接收用户操作。
- 用户在聊天界面主动发送的消息沿同一会话获得回复，聊天记录按会话结果呈现。业务 Action 仍按所属能力执行，例如设置闹钟后直接口述结果，或在闹钟窗口展示结果。

## 现有链路与迁移范围

当前 `ApplicationControl` Skill 的 `openPage` 通过 `UI.Navigation.open` 打开相册，属于本需求要撤除的模型导航路径。实施时核对模型可见的 Skill、Action 和 Tool 声明、Gateway 绑定及实际执行入口，撤除页面导航授权与旧入口的可执行路径。UI 根继续拥有手动导航，Window 继续通过独立的呈现接口管理。现有 WindowHost 位于首页层，导航页会遮挡它。用户停留在导航页且窗口无法呈现时，先口述结果或提示用户手动返回，具体跨页面呈现方案在实施时确定。[当前导航执行契约](../../MobileHarness/Actions/UI/Navigation/README.md) · [当前根页面组合](../../MobileHarness/UI/Root/README.md)

## 验收条件

- 点击进入设置、相册、历史和详情，验证进入、返回与无障碍操作均能正常使用。分别从聊天和语音请求打开导航页，核对 AI 调用无法改变页面路径或已有控件的状态。
- 模型能力目录及 Skill 中查不到旧的 `openPage` 教学或入口，直接提交旧 Action 或 Tool 也无法执行导航。
- 触发一次无界面的口述交互和一次需要用户确认的窗口交互，验证两种场景均保留原导航路径。窗口在当前页面不可见时，验证反馈与实际呈现一致。
