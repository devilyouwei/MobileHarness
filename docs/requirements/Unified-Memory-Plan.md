# 统一记录与记忆管理需求

记录日期：2026-11-04。状态：后续专项需求，尚未实施；记忆作为独立的大任务规划。

## 用户要求与本次边界

后续将用户的 WriterAgent 任务记录、聊天记录和综合记忆统一纳入 MemorySkill 管理，并评估由独立 Agent 承担记忆管理。目前仅登记需求，暂不调整 History、history-query 和 Writing Skill 的代码、注册、提示词或页面。

Writing 当前主要提供作品列表、打开和删除能力；其命名、作品管理归属及与 BasicSkill 重复的委托教学，统一留到本专项设计时处理，不单独提前重命名或精简。

## 统一管理范围

| 来源 | 后续管理目标 |
| --- | --- |
| WriterAgent 记录 | 关联任务目标、状态、各次执行、多轮请求/对话、原生工具调用与结果，以及作品目录和文件引用；支持查找、回顾和追溯。 |
| 聊天记录 | 统一查询和回顾用户对话，保留 Agent、会话、消息/请求和时间等来源身份。 |
| 综合记忆 | 基于上述真实记录整理可持续更新的摘要、用户偏好、重要事实与经历，并支持关联原始来源的检索和回忆。 |
| 作品关联 | 将 Writer 产物与任务、对话和记忆关联；作品浏览、打开、删除等能力的最终归属在专项中设计，保留文件及记录各自的生命周期。 |

MemorySkill 作为 Assistant 使用这些记录与记忆的统一能力入口，具体名称、Action 集合及与现有 history-query/Writing 的合并方式待设计。记录、工具结果和文件保持原有语义与来源隔离；综合记忆保留归纳依据和修订关系，不能覆盖原始证据。

## Memory Agent 方向与架构约束

独立记忆 Agent 是候选方向，尚未确定实现形式。框架已经存在负责历史事务的 Memory 角色；专项需评估演进现有角色及其模型、上下文、工具、工作流和生命周期，不默认再添加一个职责重复的 Agent。

后续设计需明确：记忆整理与查询的职责边界、增量更新与检索策略、任务所有权、取消/失败/恢复、队列与重试边界、来源删除或修订后的关联处理。后台整理需适配手机实际可运行机会，不承诺持续后台常驻。具体周期、预算及模型选择在实施前确定，本次不设置数值或启动后台任务。

沿用现有模块边界：Agents 拥有记忆策略与认知流程，Actions 提供业务执行能力，Gateway 承担既有通信和执行链路，Storage 管理 SQLite 记录、索引和沙盒文件，ModelKit 提供模型能力，UI 消费展示数据。专项先梳理现有仓库和公开接口，再确定存储与检索方案；不在本次增加模块、目录或数据库旁路。

## 后续设计与验收

1. 盘点 History、Writer 历史/作品、Writing 与现有 Memory 角色，明确唯一职责与统一入口，形成可评审设计后再实施。
2. 设计跨记录的稳定身份、来源引用和更新/删除语义；保留 Writer 的 taskID/runID、原生工具调用及结果配对，不套用 Assistant 的 XML 输出结构。
3. 确定 MemorySkill 与可选独立 Agent 的协作协议，以及何时检索、整理或把相关记忆注入 Assistant 上下文。
4. 验证同一用户目标能跨聊天、Writer 任务和综合记忆检索，答案可追溯，续作作品仍定位到正确任务和文件；覆盖来源修订/删除、空结果、模型与存储失败、取消及重启恢复。
5. 统一入口落地后清理被替代的 History/Writing 入口与重复教学，避免并存两套职责；代码、真实模型效果、原生页面和设备验收分别留证。

这是独立的后续专项，不将其倒算为当前 Writer 交付的未完成范围。
