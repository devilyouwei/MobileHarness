# Writer 消息倒序与底部自动加载

- 工作区消息按持久化顺序从新到旧读取，首页直接显示最近的消息。列表与详情沿用原始轮次编号。滚到底部自动追加更早消息。委托列表沿用从新到旧的委托 ID 游标，以同样方式滚动追加更早的委托。
- WriterMessages 新增按顺序游标向前查询的轻量消息页，复用投影和现有索引。WriterContainer 每页读取 21 条、显示 20 条，存在第 21 条时使用本页最旧记录作为下页游标。委托页沿用相同的前瞻语义。导出、委托详情的前序消息和运行历史继续使用各自的顺序。
- Settings 两页复用现有历史列表的自动分页组件和一次一游标的请求状态。追加失败保留记录和游标，错误时提供重试。返回子详情保留已加载记录，下拉刷新成功后从最新页重新开始。工作区的定时更新以当前最近的消息为锚向前读取一小批，刷新状态并在顶部合并新记录，不修改旧消息游标。
- 更新 WriterMessages、Writer、UI/Settings 和总体设计。验证 0、19、20、21、40 等边界、跨页顺序、轮次编号、追加与返回保留，并运行仓库检查、iOS 构建和隔离 Simulator 的滚动验收。

分页实现、SQLite 专项和页面状态测试已完成。隔离 Simulator 的测试运行器停在启动阶段，原生滚动与返回断言待执行。详见 [验证记录](../../validation/Writer-Records-Descending-Scroll.md)。
