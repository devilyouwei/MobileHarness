# 全双工播放期间的语音接纳优化

日期：2026-11-16。状态：第一阶段及 ASR 硬冷却已实现，18 个专项测试和五个 iOS 模拟器构建目标通过；完整检查存在其他失败，详见[验证记录](../../validation/Full-Duplex-Playback-Admission.md)。真机声学验收与第二、三阶段实验未完成，整份计划保留于 requirements。

2026-11-26：播放区间来源与续说等待已由 [单向语音通信](One-Way-Speech-Perception.md) 修订。

## 播放事实通过 Gateway 发布

Assistant 保留原生播放器回执和同会话播放历史，在既有 `agent.reply.activity.v1` Signal 内附带可选的有界播放快照。原有回复活动与回复 ID 仍用于静音端点和关键词目标。播放开始或结束时，即使回复活动未变，也发布更新后的快照。采集启动继续请求重发当前事实。快照最多包含 32 段，不携带音频、文字或音频句柄，以同进程的单调时钟偏移描述区间。

在现有 Agents/Support/Communication 放共享快照与历史辅助类型，Assistant Input 负责发布，SpeechPerception 保存最新的同会话副本并按原始 PCM 采集时刻在本地查询。去掉 AgentRuntime 的跨角色同步读取端口。音频处理无需等待信号，也不回放先于通知处理的 PCM。回归验证 Gateway 传输、采集时间对齐、回复活动标记不变时的原生播放变化，以及原生播放尾部规则。

打断后，Assistant 会话通过 OutputGateway 取消并加入本会话 Assistant 的 Action 和直接调用，再执行旧轮次结算。执行清理调用的返回是这一阶段的回执；原生播放停止及生成退出仍独立决定续说窗口的起点。跨角色的播放状态 Signal 用于感知门槛。

## 本轮实施修订：硬冷却与播放接纳

用户确认第一阶段与 ASR 冷却一并进入 workflow。本轮实现播放起声增量（概率 +0.15、窗口 +2，上限仍 0.95/16）、首播 250 ms 保护、结束后 200 ms 严格起声、完整 ASR 完成后 250 ms 硬冷却。两个保护窗口都丢弃未接纳音频，不缓存补识别；已有用户语句不受起播保护影响。底层麦克风/AEC/播放图持续运行。第二、三阶段依赖实机基线的自适应噪声、降音量和新语义特征仍为后续实验，不直接加入未验证规则。

冷却从完整 recognitionTurn.finish 返回时起计，空结果同样冷却；12 秒模型内部切块不触发。重置 VAD、前滚及重采样/增强缓存，按原始 capturedAt 同时拦截原始 PCM、已生成的 DSP 输出和排队旧包。以至多 32 ms 的处理片段保守丢弃跨保护边界的片段，因此最多增加一个片段的等待，不补送被保护的样本。首次采集及显式停止/代际替换清除门限。

播放事实使用原生首块 schedule 后回调的单调时间；回调产生至多一个被播放生命周期加入的发布任务，结束等待开始通知完成后发布配对终态。Assistant 保留最多 32 个播放区间，400 ms 内同会话片段共用 burst 起点；历史淘汰后带 coverage 边界，早于可证明历史的音频拒绝并计数，不将未知旧 PCM 当作静音期。SpeechPerception 通过只读快照查询，保留捕获时间映射，不添加音频事件队列。

修改文件除上表外包含 Agents/AgentHostBindings、Agents/SpeechPerception/VoiceAgentSession 以及 Actions/Speech/Listening/VoiceSessionConnections 的播放回调时间参数；类型与策略放在现有 SpeechBoundaryPolicy.swift，避免新增目录。同步 DeepFilterNet3 文档的“每句不重置缓存”描述：显式 ASR 冷却现在必须清理缓存。DSP 输出切片使用 capture-scoped 严格递增序号，不复用大包序号；回归替身保留真实 Silero 的序号校验。回归覆盖空结果冷却、缓存晚到、起播保护、分片合并、维持门槛及取消隔离；既有合成测试须使用与 capturedAt 一致的时序，不将极速注入音频误当真实时间。

## 目标与范围

用户反馈 assistant 播报时容易把外部声音识别为用户输入，要求规划播放期间动态提高门槛、起播短时不做 ASR 的优化。本计划同时覆盖手机外放残余回声与耳机环境声，具体优先路线待实测确认。保持正常双讲和语音打断，不恢复整段播放期间禁用识别的半双工方案。

成功标准不是减少所有识别次数，而是降低误字幕、误入队和误打断，同时保留低音量用户及“停”“等一下”等短指令。单纯提高 VAD 概率阈值不能判断人声是否对设备说话；旁人/电视中的清晰人声仍可能通过。因此分别记录自身回声、非语音噪声和外部真实人声，不能统称 AEC 故障。

## 初始基线与缺口

- `SpeechPerceptionAgent` 在 capture 启动时快照检测设置，逐帧使用固定 threshold/onsetWindows。默认 0.65、8 个 512 样本窗口（16 kHz 下 256 ms）；允许范围 0.05…0.95、1…16 窗。
- `SpeechBoundaryPolicy` 用同一阈值判断起声与语句中人声/静音。直接全程抬高该值会同时影响尾音、停顿和端点，需拆分起声门槛与已确认语句的维持门槛。
- `speechEndpointActivity.replyActive` 同时表示模型工作、待执行结果或播放；它目前只控制端点的 800/512 ms 静音选择，不能当作实际播放起点。
- `VoiceNativeEffects` 在首块流 PCM 取出后通知 activeChanged(true)，早于 native schedule。`AppleAudioIO.playStream` 已有首块 schedule 后的 onStarted 回调；该事实仍是原生开始/调度观测，不宣称等于扬声器声波到达人耳的时刻。
- PlatformKit 已用同图 Voice Processing 处理采播。Apple 的回声处理能力不等于已验证本环境的误触发率。本阶段不叠加第二套 AEC。
- 可选 DeepFilterNet3 窗口处理首次输出约需积累 400 ms 输入。处理后 PCM 可能晚于起播保护窗口出队，必须按原始采集时间而非消费时间应用保护，防止过期音频补送入 ASR。
- Assistant 的 Decision 在最终 ASR 后才运行，当前保护有效用户输入的规则也可能把误识别成有意义句子的内容入队。只改 Decision 不能解决前面的误字幕。

## 分阶段方案

### 第一阶段：播放事实、起播保护及动态起声门槛

SpeechPerception 自有的播放感知接纳状态放在现有目录内。播放未开始时继续使用用户设置；起播保护窗口只约束新的 ASR 语句，不切断已确认的用户语句，不停止采集、AEC 或降噪处理。

下表全部为实验初值，不是已验证默认值。先以诊断配置固定快照实现，避免一开始增加大量用户滑块。

| 状态 | 起声/ASR 行为 | 初始实验参数 |
| --- | --- | --- |
| 空闲/仅思考 | 现有起声设置，正常 ASR | 默认 0.65、8 窗不变 |
| 首次起播保护 | 保留底层采集，丢弃保护片段，不进入 VAD/ASR 或补送 | 250 ms；对照 0/150/250/350 ms |
| 稳定播放 | 更严格的起声确认，通过后把确认候选及受控前滚送入 ASR | T_on=min(0.95, base+0.15)，N_on=min(16, base+2)，默认对应 0.80/10 窗（320 ms） |
| 用户语句已确认 | 固定本句的维持门槛和端点策略，不能因下一句 TTS 开始再次封口 | 维持阈值沿用本句基础设置；不与更高的 T_on 共用 |
| 播放结束/取消尾部 | 短暂保留较严格起声条件，再回到基础值；已确认用户语句继续 | 200 ms；对照 0/150/250 ms |

起播窗口实施契约：

1. 根据原生开始事实、会话、播放 ID 和单调时间建立窗口；起播前已有用户语句直接继续。模型开始生成、字幕出现或 TTS 合成开始不触发窗口。
2. 窗口内的新语句 PCM 直接丢弃，VAD/ASR 不接收；清理前滚及 DSP 缓存，不在到期时补送。底层原生采集/AEC 保持运行。窗口内开始且结束的短词可能丢失，必须按验收矩阵测量，不能宣称完全保留。
3. 同一 burst 首片触发一次，400 ms 内相邻片段共用首片起点，后续片段不能延长窗口。真正结束后再次起播才重新判断。
4. 没有新增候选 PCM 队列或异步音频任务；原始片段至多 32 ms，处理后片段至多 512 样本。跨边界片段保守丢弃，最大多等待一个片段。
5. 捕获时间在 DSP 前后双重校验；增强开/关、慢消费和排队旧包不能把已屏蔽区间带回识别。
6. 有起声的完整 ASR 收尾后 250 ms 硬冷却，包括识别为空的语句。无起声静音端点及同句最大时长切块不触发。冷却由数据时间判定，无页面计时器；关闭、代际替换、暂停/恢复及失败恢复清除旧门限。

### 第二阶段：环境自适应与误触发归因

第一阶段完成设备 A/B 后再加入，避免同时改变过多变量：

- 在未确认人声、非起播过渡时估计有限时间窗噪声底；对起声候选增加相对能量裕量（如 6–10 dB 的实验范围），不使用一个固定绝对音量覆盖所有手机/耳机。说话时冻结基线，避免用户/回声把噪声底越抬越高；噪声底不是用户身份判断。
- 已确认用户语句可试验轻微降低 assistant 的播放增益，改善后续双讲条件；由 Actions 请求 PlatformKit 的通用增益能力，并在取消/结束/替代时恢复，不能靠视图存活维持。不要把 Apple 的 other-audio ducking API 误当作本应用 TTS 的专用 ducking。
- 如仍主要是自身回声，再评估对齐的播放参考与近端证据；文本相似度只能是诊断/联合特征，不能因用户重复 assistant 的词就直接删除输入。
- 如主要是旁人/电视，独立评估面向设备说话检测、可用声源方向或显式交互模式。现有声源估计不提供说话人身份；不承诺仅调 VAD 或通用降噪可区分旁人与用户。不在本阶段引入声纹采集或新模型依赖。

### 第三阶段：必要的 Decision 协同

保留声学接纳与语义打断判断的分工。前两阶段仍不足时，向 Assistant 提供受信任的播放重叠、声学接纳原因和置信不足标记，帮助区分有效用户输入与不确定语音；不把模型输出的 enqueue/discard 当作声学真值。需重新审查当前“有意义文本覆盖 discard”的规则，不能无差别放宽或静默吞掉有效请求。

| 所有者与预期文件 | 变更职责 |

状态归属于采集会话，不归属于页面。关闭聆听、capture generation 替换、路由重建、中断、失败清理都清除候选与播放窗口，迟到事件按会话/代际/播放身份拒绝。沿现有串行拥有者更新状态，不为每包 PCM 新建 Task；时间窗口按单调时间计算，无页面计时器。播放事实使用最多 32 个区间的只读快照，无事件队列；淘汰携带 coverage 边界，过旧未接纳音频保守拒绝并计数。未知旧音频不能当作已验证静音。

## 验证与发布门槛

先记录原版基线，再比较：A=现有；B=只动态起声；C=动态起声+起播窗口；D=加环境自适应。设备/路线、音量、距离、房间、降噪开关保持可比，参数不得边测边变。首阶段先选择 B/C，不一次叠加 D。

- 自动化：播放开始/首块延迟/失败未出声、连续 TTS 分片不重复保护、跨边界 PCM、已有用户句不被切断、窗口内短词、静音/弱噪声拒绝、真实双讲、基础高阈值上限、旧 stop/取消/重新开启、降噪延迟及缓存溢出。
- 实机矩阵：手机外放和 AirPods；低/中/高音量；安静、风扇、电视/旁人；用户在起播前、起播后 0/100/250/500 ms 和稳定播放时说话；覆盖“停”“等一下”、轻声和长句。分别比较增强开/关，记录实际设备和版本。
- 度量：每 10 分钟无人指令时的误字幕、误入队、误打断次数；短指令召回率；正确识别首字率；用户真实起声至实际停止播放的 P50/P95；ASR 提交等待及端点等待分别计时；CPU、延迟和队列溢出。
- 暂定产品门槛：相对基线误入队/误打断至少降低 70%；每路线至少 30 次短指令的召回不低于 95%；稳定播放的额外接纳 P95 不超过 150 ms，起播窗口内不超过 350 ms。小样本仅作首轮筛选，不能表述为统计保证；绝对端到端打断延迟仍需报告，不能只公布增量。基线过低时报告原始次数，不计算不稳定百分比。
- 不达标时依次缩短保护窗口、降低播放起声增量或关闭该策略；保留原有全双工基线作对照，不通过延长屏蔽期获得表面改善。
- 实施后运行 `./scripts/check.sh` 与 `./scripts/build-ios.sh`。真机声学验收是本计划的完成条件；编译、替身模型与模拟器测试不能替代。

诊断仅记录阶段、阈值、候选持续时间、能量区间、拒绝原因、播放/capture 代际与时延，默认不保存原始音频或文本。附加音频录制需用户明确授权。

## 语音链路复查与整理（2026-11-20）

触发：真机仍出现自身播报被识别、环境声被识别。复查 PlatformKit/Audio 与 Agents/SpeechPerception 后确认：

- 原生采播图已在输入/输出节点同时确认 Voice Processing 启用且未旁路（`AppleAudioIO.prepareCapture`、`voiceProcessingEnabled`），启动后、首包后、配置变化和播放提交前复核；未发现遗漏的节点配置。系统回声处理的实际残留量只能由真机基线给出，代码阅读不能把误触发归因到某个未设置项。
- 降噪失败按既有契约显式失败并走识别恢复，不回退为原始 PCM；该契约保持，不新增静默回退。

## 后续需求：更自然的全双工打断（2026-11-22）

### 目标与边界

在保留及时打断和完整接纳用户输入的前提下，降低误打断、避免用户尚未说完就回复，并让后续模型请求知道用户实际听到了什么。当前并非起声即打断：用户语音经 VAD 与 ASR 得到 final 文本并进入 Assistant 输入队列后，由独立 Decision 判断 `interrupt`，判定为打断才取消 LLM、Action 与播放，其结果可为否。此前草稿写成起声后一律打断，是错误前提，已更正；下列评估须以该实际链路为基线，在核对 `AssistantInputDecision.swift` 的实际触发条件后再定具体方案。打断成功后的 40 窗一次性探测及确认起声后等待 ASR 终态的要求见[轮次结算需求](Assistant-Channel-Settlement.md#打断后一次性语音窗口探测2026-11-22)，本节不改变该契约。以下是待评估的需求方向，不表示已经实现、选定具体方案或完成真机验证；各项实施前须确认方案和影响范围。

### 优先评估：播放进度与对话上下文

- 区分模型已生成、语音已合成、已提交播放与实际播放进度；不能把整段生成文本视作用户已经听到。打断后提供与播放身份对应的可证明进度，让后续模型上下文表达已播放部分和被中断事实；对齐精度不足时保留不确定性，不能伪造逐字播放边界。
- 查明现有 TTS 分片、原生播放进度、文本对齐、历史存储和模型上下文的实际能力，先确定可支持句级、分片级还是更细粒度；区分设备输出与用户实际听到的不可观测差异。未播部分不作为已听内容传给模型，但不得丢失已有生成记录、执行记录或工具配对。
- 进度、播放完成及打断结算按会话、轮次和播放身份隔离；处理未起播、部分播放、快速替代、失败、迟到回调和重启恢复。用户可见历史与模型上下文的呈现方式须明确设计，不能仅修改 UI 状态后假定模型上下文同步。

### 打断后按已完成的 Action 重建回复

状态：已按 2026-11-26 用户澄清实施。当前范围见[跨轨道回归](../../validation/Full-Duplex-Playback-Admission.md#打断后按已完成的-action-重建回复)。原有按 `speak` 播放进度截断的构建和安装见[历史验证](../../validation/Full-Duplex-Playback-Admission.md#打断后按播报进度截断回复)。

Assistant 接纳有效打断时，锁定当前请求中已经发出的 Action 集合。清理确认后，按全局入轨顺序拼接所有已收到成功完成 Signal 的 Action 所对应的原始输出片段。成功回执可在清理期间到达，完成顺序不改变拼接顺序。失败、部分失败、取消及未执行的 Action 只保留执行证据，夹在中间也跳过。`speak` 遵循同一终态规则。字幕和播报由同一段自然文本映射时，任一 Action 成功完成即保留该段一次。没有成功完成的 Action 时，正文保留空串。

截断在被打断轮次结算时提交。下一次模型请求使用已结算的正文和结构化中断标记。若工具结果已入队，随工具调用携带的 Assistant 文本也换成同一份已结算正文。截断正文和标记一并保存，原始生成证据、Action 完成状态及工具调用配对按既有契约记录。按会话、轮次和 Action 身份绑定结算，清理终态之后的回执不能覆盖结果。

实施范围：共享 Function Token 解析与句子分段携带原始 UTF-8 范围。Assistant 通过有序输出绑定请求、`callID` 与文本片段，用已有的 `actionFinished` Signal 确认成功。原执行收尾先等待轮次结果投递，再发打断清理终态。Assistant 收到该终态并加入生成清理后，从原始响应拼接已完成片段，通过历史写入屏障将正文和完成 Action ID 一起落盘。移除仅为语音截断添加的 PCM 单元回执及分段合成。同步相关源码 README 与总体设计。

验收覆盖不同轨道先后入轨、反序完成、取消或失败动作插在成功动作之间、清理期间送达的成功回执、`speak` 与非语音 Action 混排、没有符合条件的 Action，以及重复 XML、转义和多字节文本。核对拼接结果、SQLite 重读及下一次模型请求，保留原始生成和工具执行证据。

### 优先评估：附和与有效打断

- 现有 Decision 已在 ASR final 之后区分打断与否，需先量化其对“嗯”“对”等附和、短促噪声和有意打断的判定表现及延迟（须等 VAD 尾端点与 final 识别），再确定缺口：是提示词/模型判定不足，还是延迟过长。避免简单地按词表或时长丢弃输入：同一个短词在不同上下文也可能表达停止、纠正或新请求；轻声和短指令尤其需要保护。
- 声学起声、ASR 内容与 Assistant 的语义决策各自保留职责。若评估更早的响应（如结合部分识别结果，或起声后先暂停播放），须比较其与现有 final 后判定的延迟和误判；部分 ASR 可能不稳定，不能把尚无文本直接视为无效输入。不确定时的处理策略及是否允许继续播放须在实施前确认。
- 附和是否进入历史或下一批上下文、错误判断如何恢复、用户能否明确停止，均须定义并测试；不得绕过现有有界队列或静默丢弃有效输入。

### 后续候选：误打断恢复与语义端点

- **暂停、确认及恢复**：评估在 Decision 出结果前先暂停或淡出播放（须先核对当前判定前的播放行为），判定有效后再取消；如确认为误触发，可在仍拥有有效播放数据和身份的条件下恢复，否则显式结算并选择经确认的后续行为。暂停窗口、资源容量、超时及取消所有权须有界。已执行或正在执行的 Action 不等同于可恢复的音频，不能假设可撤销或重复执行；安全相关停止必须保持及时且独立于误打断恢复。
- **语义轮次结束判断**：评估结合音频和/或文本区分短暂停顿与真正说完，避免固定静音端点过早截句或无谓等待。先比较现有 VAD/ASR 基线，再决定是否需要额外模型或服务；模型能力应通过现有 ModelKit 边界接入，失败、超时及不可用时使用经过明确设计的既有端点路径，不得无限等待。不得用语义推测替代 ASR final 实际入队。
- **声学与采集时间**：继续按本需求既有第二、三阶段分别评估回声、环境声与真实用户语音；VPIO 回调的采集时间精度限制另见[验证记录](../../validation/Full-Duplex-Playback-Admission.md#打断后-40-个语音窗口)。如要改善时间映射，先验证可用平台时间源、跨缓冲对齐及异常处理，不以未经验证的时间戳声称提高精度。

### 预期归属与验证

播放进度事实由 PlatformKit/Audio 提供通用能力，Actions/Speech 负责播放执行及身份，Assistant 负责轮次、打断决策与模型上下文，Storage 负责持久化契约；SpeechPerception 负责 VAD/ASR 事实，AgentRuntime 只做窄接口装配。具体接口、文件和是否需要模型，须在实施前根据现有代码和实验结果确定；不引入基础模块对上层业务的依赖。

先记录可复现基线，再分项比较，不将多个未验证策略同时上线。自动化覆盖播放部分完成和未起播、身份隔离、错误及取消、短指令与附和、ASR 空结果/迟到、误打断恢复、语义端点超时和既有 40 窗屏障回归。真机分别覆盖外放与耳机、不同音量和噪声、用户轻声/短指令/思考停顿，记录误打断率、有效打断召回、起声至停止播放的 P50/P95、用户说完到回复延迟和上下文错认已播放内容的次数。指标门槛及样本量在实验设计时确定；模拟器、替身测试和编译不能替代物理设备及真实模型验收。

具体实现获确认后先补充相应技术需求和文件级计划，完成后同步受影响的模块 README 与跨模块设计，并分别记录定向测试、`./scripts/check.sh`、完整 Xcode 可用时的 `./scripts/build-ios.sh` 和真实设备验收结果。

## ASR 声量自适应准入（2026-11-28）

在现有 VAD 分段上增加端侧声量准入。目标是过滤较弱的环境声和远处人声触发，保留轻声尾音、句内停顿和短指令。电视与用户同时说话时的语音分离留给独立的设备验收和后续模型评估。

- `SpeechBoundaryPolicy.swift` 拥有声量策略。用准备后的 16 kHz 单声道窗口 RMS（dBFS）和 VAD 分数共同判断起声及句内维持。保留原有起声概率、连续样本数、播放增量、前滚、端点补边及切块。未接纳窗沿现有静音与端点流程。空转写主动封口后的 160 ms 重入等待用基础 VAD 分数与维持电平判断安静。
- 空闲且 VAD 明确不认为有人说话时更新噪声底；候选起声、已确认语音、播放及其 200 ms 尾部冻结学习。噪声底采用按样本数更新的有界平滑估计。起声与维持分别要求高于噪声底 8 / 3 dB，设绝对上下界。确认语句的高置信非重叠语音只留至多 32 个窗口电平；常规端点且得到非空终稿后，以至少 8 个合格窗的中位数初始化会话说话电平，后续单句更新最多 2 dB。用参考值减去 12 / 20 dB 得到起声 / 维持参考门槛，分别最多抬到 −44 / −54 dBFS。拒绝用有播放重叠、空结果、失败或主动无文本封口的语句校准。
- `VoiceActivitySegmenter.swift` 在当前顺序消费者内应用策略；`SpeechPerceptionAgent.swift` 提供基于采集时间的播放事实，在重置时传入有效终稿结果，并在采集代及原生采样率或声道布局变化时清除校准。普通转写结束保留估计。沿用原有 DSP、FIFO、模型和生命周期接口；让声仍按确认起声后的实际电平处理。起声诊断记录当前两档声量门槛和噪声底，仅输出数值。
- 同步 SpeechPerception README 与总体语音数据流。Swift 回归覆盖弱高分噪音拒绝、噪声底适应、播放冻结、近端首句与后续弱声、句内弱音与静音端点、空结果不学习和路由重置。真机分别记录电视独播时误提交及混合说话时字错率、轻声和短指令召回；用数据判断人声隔离模型的必要性。
