# Zipformer 流式打断

## 接入计划

ModelKit 的 Speech/KWS 负责 Hugging Mac 固定修订的 Core ML encoder、decoder、joiner、
16 kHz 滤波器组和流式关键词解码。用现有模型清单、下载和资源生命周期托管；App 前台启动
准备已安装制品，并监听前台安装状态变化。未安装或尚未准备时，语音通道不等待，也不发起下载。

SpeechPerception 从 VAD 首个起声候选窗口开始给独立的打断探测任务送 PCM，带上有界预卷。
同一次候选的模型缓存延续到起声确认及后续窗口，候选撤销、端点、采集结束和目标回复变更时失效。
探测队列有界，失败或积压时关闭该轮快速探测并保留 ASR。只有全双工、同一采集代际、起声已确认且
目标回复仍匹配时，命中才可通过 Gateway 发布现有的 AssistantInterrupt。每轮最多发一次。

Assistant 发布其活动回复的精确 ID 并复用现有目标校验和停播入口。ASR 始终继续；快速打断成功后，
同一语句正常入队，跳过重复的打断 Decision。无命中、未安装、快速路径不可用或未成功停止时，最终
ASR 文本走既有 Decision。关键词检测默认关闭，在设置的语音页显式选择 Zipformer 后启用快速停播。
默认启用须另行取得真实麦克风与误停播证据。词表和门限取自旁路候选，现有实验结果作为基线。

实现后同步 ModelKit、SpeechPerception、Assistant 输入、App 组合与总体技术说明。验证覆盖制品
加载、PCM 特征、起声和回复代际、缺模型、超出队列容量、迟到结果及 Decision 补判。真实模型在
Mac 以合成语音检查，真机上线证据单独记录。

## 设置入口

语音页的[关键词检测模型菜单](Speech-Model-Selection.md)采用现有资源清单呈现下载和安装状态，
只有已安装时可选择 Zipformer。Actions 通过原有的模型资源偏好事务保存该选择，无旧偏好时读取为关闭，
移除制品后恢复为关闭。ApplicationControl 负责保存请求的校验与派发。SpeechPerception 每次新采集
读取快速打断偏好。读取失败时仅观测已确认的命中，语音采集和最终 ASR Decision 正常执行。

## 当前验证与启用条件

Swift 定向验证覆盖 Kaldi 特征、冷模型跳过加载、观测门限、已确认语句快停及最终转写补判。
真实模型测试使用固定的 Hugging Mac Core ML 制品与独立合成的英文口令，在 Mac 上命中。
模拟器构建脚本的五个 scheme 均通过。
`check.sh` 停在现有 Agent 资源归属和 State Value codec 静态检查，未运行脚本内的后续 Swift 测试。

iPhone 真机的采集、回声、误停播和端到端响应仍需验收。

设置回归覆盖旧配置默认关闭、未安装拒绝启用、通过资源 Gateway 保存后恢复、移除后自动关闭，
以及保存失败时保留已确认的开关状态。设置测试同时验证 App 所用的语音感知发布注册。

## 单独停播口令与链路排查

设置选择 Zipformer 的 iPhone 上验证安装状态和偏好。对已安装制品的前台预热记录就绪结果，
快停候选在麦克风热路径仍只取得已准备的会话。为词表补充独立的 `stop` 和「停下」，短口令需要
连续的尾随 blank，并保留原有 160 ms 尾部静音、全双工、语句确认和目标校验。较长口令保持原门限。

最终 ASR 仍请求选中的 Decision。若模型没有批准停播，已确认且完整转写恰好为这两个独立口令之一时，
活动语音会话仍请求同一个受目标围栏保护的停播入口。保留实际模型结论，避免把口令规则记成模型命中。
其他转写继续由 Decision 判定。工程回归覆盖短口令与长口令的前缀关系、口令限定、误匹配和 Decision 补判。

## 设置中的关键词测试

设置语音页首屏先显示音频检测，然后连续显示模型配置。关键词模型选择下方提供独立的 10 秒麦克风测试。UI 与 ApplicationControl 沿用现有诊断请求、停止和超时流程，音频检测和关键词测试互斥。

Actions 继续管理本机采集和诊断状态。SpeechPerception 使用现有 PCM 预处理、同一个已选关键词能力和生产词表。测试绕过 VAD、回复目标和打断信号，显示首次原始命中的具体短语及生产尾部静音门限是否通过。未命中、模型未就绪和采集失败分别显示。页面离开、后台和显式停止均撤销采集与模型租约。

针对真机有原始麦克风电平但无命中的情况，用完整词表和固定 PCM 对比发布版宿主、App Swift 宿主与输入预处理。区分原始麦克风帧、送达模型的 PCM 和模型命中。

独立短词从解码会话的首个词元计算。设置测试遇到至少 600 ms 的低电平后，在下一次起声重开关键词会话并保留最多 100 ms 预卷，允许同一测试内再次尝试。测试同时呈现已由模型接收的时长和处理后的电平，正式打断的词表和判定门限不变。

## 关键词置信度设置

关键词检测下增加和 VAD 同样交互的滑块。默认 0.25，范围 0.10…0.60，步进 0.05。沿用模型资源偏好的保存、校验和失败恢复事务，旧记录读作 0.25。正式快停和设置测试分别在采集开始时读取并固定该阈值，测试内重开的关键词会话继续使用该值。Zipformer 以该值比较关键词词元的平均置信度。独立短词限制、尾部静音和 VAD 的配置保持独立。验证覆盖旧记录、保存恢复以及同一解码候选在两档阈值下的不同结果。

## 快停后的续说窗口

跨角色的协议和实施边界见 [统一执行反馈与续说等待](Action-Execution-Lifecycle.md)。全双工语音会话从 Assistant 接纳打断时开始观察 64 个实际处理的 VAD 窗口，和当前会话的 Action 取消与清理并行。候选和在途语句持续跟踪，清理期间接纳同会话已确认语句的终稿。旧回复的输出结束与清理完成属于放行条件，无需等清理后再开始计数。

快停口令的 ASR 终稿照常入队。同一轮内连说的后半句随终稿一并交付。接纳前已经出现的候选与之后到达的候选使用同一生命周期，等待候选清除，或确认起声并等待 ASR 终稿入队或空轮结束。采集更换后重新累计窗口，保留已确认的 Action 清理结果。显式暂停、停止或关闭语音会话时退休观察。快停接纳时立即记录语句 ID，防止同一句终稿重复触发 Decision。
