# Camera session image cache and gallery

2026-11-06 approved implementation plan. User approved Storage/Cache/Image alongside Audio, FIFO after 20 images, stable IDs inside one open-window lifetime, cache retention during minimization/background, unload-on-disposition, and one close confirmation for unreviewed photos.

## Ownership and behavior

StorageCache Image owns a dedicated 112 MiB session cache: at most20 original JPEGs (4 MiB each), derived analysis bytes (1 MiB each), one4 MiB capture reservation. IDs preview_N are memory-only, restart at1 on a new camera window session; append succeeds before FIFO retirement, failed/cancelled capture does not evict. CacheContainer owns session shutdown. Entries retain metadata and Camera-written disposition flags. Remove persistent preview-number allocation from MediaRepository/MediaStore/SQLite without changing album media_N.

Actions/Camera owns the model State, default latest plus at most3 explicit selections per context, prepare/load/unload, save, UI catalog and window lifetime. Save unloads but retains originals and flags; repeated saving is idempotent. Reshooting preserves earlier cached photos for explicit loading; closing clears unsaved previews. Hidden session references fence history and queued model/UI operations against reused IDs. History reads new session references only from matching live cache; legacy unscoped references expire without album lookup (updated by the2026-11-07 decision below). No unsaved bytes are persisted. Minimized/occluded/background windows retain cache while withholding model attachments; only actual window close clears it, independently of Face vision capture. Closure rejects new work and joins preparation/disposition/capture before release; committed saves survive cancellation. Close asks once for unreviewed photos, with return or clear choices; video handling remains separate.

Agents shared Context/Chat carries private reference bindings outside model JSON, records them in historical attachment metadata, and attaches images to the original input as before. Typed ActionExecutionContext carries request-time resource bindings; model actions validate the captured scope, while direct UI inputs bind the current session when submitted. No internal/UI Action triggers ReACT.

UI/Camera receives typed catalog/read interfaces from Camera. Right-bottom stack shows latest three thumbnails and total count; expands within the same window to previous/save/ignore/next controls, index/count and disposition. Swipe paging only at fit zoom, double tap fit/2x, pinch1...4x and pan; arrows always page/reset zoom. Save/ignore remain on page. Evicted selection moves to first retained image. Decode only current/neighbors and small stack thumbnails. Replace fixed opaque bottom area with controls over full-window live video using a translucent dark gradient; cache presence no longer locks shutter/lens/mode. Preserve capture/feedback completion and accessibility/Reduce Motion while removing obsolete photo departure-as-removal behavior.
