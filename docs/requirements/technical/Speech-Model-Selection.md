# 语音模型选择与资源分组

## 实施计划

设置的 AI 模型入口按语音、视觉、智能体排列。语音合并识别与合成页面。页面依次
展示 VAD、降噪、关键词检测、ASR 与 TTS 的菜单，起声窗口和概率阈值归入 VAD。
下载源在独立下载区首行，资源按同一能力顺序分组。已安装的资源可选，下载本身不改当前选择。

ModelKit 发布可选能力与稳定模型 ID，并在每项能力的现有协议后解析所选模型。默认是能量
VAD、关闭降噪和关键词检测、Apple 系统识别和合成。Apple ASR ID 对应现有语言路由。
读取旧的识别、合成、降噪和关键词布尔偏好时，解析为原先选中的模型 ID，下一次保存写入映射。
旧记录没有 VAD 选择时使用能量。缺失资源恢复为对应默认，运行中的会话仍由原租约收尾。Zipformer 的已安装
预热独立于选择。

Actions 保存和校验能力到模型 ID 的映射，把 ModelKit 的候选与制品状态投影给 UI。
ApplicationControl 继续负责有界的资源偏好事务与绑定。旧的识别、合成导航请求保留为
兼容入口，显示同一语音页面。能力菜单不感知具体 Core ML 或系统实现。

实现后同步 Settings、ModelKit Speech 与资源管理、App 组合和总览文档，验证旧偏好迁移、
缺失模型回退、下载不自动选中、能力之间的独立映射和导航。

## Kokoro 合成与音色

- 在 ModelKit 的制品目录中固定 FluidInference/kokoro-82m-coreml 的版本，按现有 Hugging Face 下载流程安装两套 Core ML 图、发音资源和音色。Kokoro 注册为独立、可卸载的 TTS 提供者。下载只安装制品，Apple 仍为默认；删除沿用合成资源的停用流程。
- Settings 从 ModelKit 的候选投影读取中文和英文音色。仅在选中 Kokoro 时显示语言和音色菜单。以独立的音色 ID 保存用户选择，通过 ApplicationControl 和 Actions 的现有偏好事务绑定到 ModelKit。切换语言选择该语言的默认音色，兼容无音色字段的已有设置。
- Kokoro 在受管推理会话开始时获取音色快照。所选语言的文本段使用所选音色，混读的另一语言段使用该语言的默认音色。所有音色读取已安装的本地文件，保持现有 PCM、租约与取消契约。
- 同步 Settings、ApplicationControl、Actions ModelResources、ModelKit Speech / TTS / Kokoro / Management / Config 和总体设计。验证制品清单、音色路由、持久化和缺失制品回退，并分别记录工程检查、原生构建与真实模型验收结果。

上游制品树超过单页返回上限。ModelKitHub 在创建下载计划前读取同一 HTTPS 源和
同一版本路径的所有分页，限制总页数和条目数，沿用已保存下载计划与后台传输。
Kokoro 下载验收允许显式指定临时制品根，从同一持久化下载计划续传，再通过默认
合成端口验证音色；默认使用测试自有的临时目录。
