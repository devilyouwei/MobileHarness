# 视觉跟随目标切换

状态为待实施。现有视觉／跟随入口使用 YOLO 人体姿态，Face 的眼睛可从姿态关键点估计人脸方向，Photographer 可基于新鲜姿态生成设备跟随目标。本需求在同一入口增加语音指定目标和运行中切换，覆盖模型、设置、Action 和持续跟随逻辑。[当前视觉链路](../../MobileHarness/README.md#13-camera-preview-vision-and-tracking) · [摄影跟随现状](../../MobileHarness/Agents/Photographer/README.md)

## 用户场景

| 跟随目标 | 语音示例 | 跟随依据 |
| --- | --- | --- |
| 手 | “跟随我的手”“切换成跟手” | 可见手部的区域或手部关键点 |
| 脸 | “跟随我的脸”“改成跟脸” | 可见人脸的位置，无需识别人物身份 |
| 人／全身 | “跟随人”“跟随我的全身” | 人体框或可用身体关键点，兼容既有人体姿态跟随 |
| 动物 | “跟随动物”“跟随那只猫” | 已选模型支持的动物类别。明确指定物种时按该类匹配，设置页列出可用类别。 |

- “开始跟随”省略类型时继续使用本次会话选中的目标，未选择时使用“人／全身”。首次说“跟随我的手”可用一次请求开启视觉／跟随并选择手部模式。运行中说“改成跟脸”只切换目标，复用健康的相机采集。关闭或停止沿用现有视觉／跟随入口。
- 跟随模式表示用户希望追踪的类型，锁定状态表示当前是否看到并跟住了某个实例。切换已生效但画面暂无匹配目标时，反馈“已切换为跟随手，正在寻找手部”等真实状态。模型未安装、不支持目标、相机无权限或切换失败时，说明阻塞原因和实际处于的模式。
- 跟随与拍照、录像仍使用独立的业务入口。摄影任务的自主构图和运镜由[摄影构图与运镜需求](Photographer-Proposal.md)跟踪。

## 语音、Action 与状态

- Assistant 通过现有 Agent／Skill 调用链理解跟随意图。扩充 ApplicationControl 的 `Vision` 教学和中英文示例，将“人”“全身”等说法映射到同一类型。意图明确时直接提交 Action，无法确定目标时先询问。
- 在既有 `Camera.Perception` 下增加类型化的切换跟随目标 Action，拟用 `Vision.setFollowTarget` 作为模型侧别名。参数包含 `hand`、`face`、`person`、`animal` 等目标类型，动物可带模型支持的类别。复用现有 Vision 通道、权限和执行回执，拒绝无效参数。回执区分已切换但仍在寻找、已经锁定、不可用和失败，并提供实际生效的目标。重复设置同一目标不重启健康采集。
- Actions 侧相机／视觉业务保持唯一的运行模式和切换事务。跟随结果与故障走现有受保护端口和 Gateway，公开状态只提供所需的有效目标类型、模式状态、模型是否可用和失败原因。切换期间使旧模式的观测和控制输出失效，最后的回执以实际结果为准。[现有相机 Action](../../MobileHarness/Actions/Camera/README.md)

## ModelKit 与视觉模型设置

- ModelKit 增加或扩展视觉能力和模型注册，保留现有姿态模型，并提供覆盖手、脸、人／全身和受支持动物的真实模型或系统视觉适配器。一个模型可支持多种目标，也可由多个模型分担。具体制品由实现阶段根据真实设备的识别效果、延迟和资源占用确定。
- 模型目录公开模型身份、版本、支持的目标类型／动物类别及安装与就绪状态。统一观测提供目标类型、置信度、可用于跟随的位置或关键点、帧／采集身份，并在模型能提供时附带目标关联标识。适配器封装模型输出差异、坐标转换和运行时细节；目标锁定与动作策略归业务层。[现有视觉模型注册](../../MobileHarness/ModelKit/Support/Management/VisionDefaults.swift)
- 更新 UI Settings 的视觉模型页和现有模型资源请求链路，按目标显示兼容模型、当前选择和下载／安装／可用状态。用户可在现有设置流程管理模型。同一个模型可满足多个目标的选择；旧用户的人体姿态配置继续有效。缺少匹配模型时，语音反馈指出缺失能力，用户可手动进入设置完成安装或选择。[视觉模型设置](../../MobileHarness/UI/Settings/ModelResourcesView.swift) · [用户导航边界](Manual-Navigation-and-Agent-Interaction.md)

## 跟随逻辑与验收

- VisionPerception 按模式消费相机帧并发布新鲜观测，延续单次在途推理与最新帧覆盖策略。跟随业务按有效目标类型筛选并稳定关联实例，多候选时按明确规则锁定，短时遮挡后仅在能可靠关联时恢复原目标。目标丢失、过期或无法区分时撤销输出，等待有效观测或用户重新指定。
- Face 的视线和经授权的设备跟随使用同一个当前有效目标。模式切换、镜头切换、停止、后台、权限撤销和设备断连均须清理旧目标；迟到帧和旧控制命令不得再次生效。设备跟随复用既有授权、资源租约、运动约束和手动接管，记录感知锁定与设备实际响应。[视觉感知](../../MobileHarness/Agents/VisionPerception/README.md) · [设备跟随](../../MobileHarness/Agents/Photographer/README.md)
- 工程验收覆盖四类语音意图到 Action、同义词、旧人体配置、错误回执、切换竞态、目标丢失、迟到结果、模型缺失和相机采集复用。真机分别验证 Settings 模型管理、各类型真实识别和跟随、运行中切换、停止和手动接管。记录切换至锁定的时间、目标丢失至撤销输出的时间及误跟随情况，分别保存软件验证与实际设备结果。
