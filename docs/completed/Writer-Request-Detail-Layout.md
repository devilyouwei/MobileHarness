# Writer 请求详情布局与接口

2026-11-08 实施。验证证据见 [Writer 请求详情](../validation/Writer-Record-Detail.md#五区块请求详情2026-11-08)。

## 展示与交互

- 请求详情依次为本轮概览、本轮输入、本轮工具调用、本轮产出和调试日志。概览显示轮次、操作、阶段、已知目标、重试、时间、可复制的请求 ID，以及彼此独立的模型和工具状态。输入独立于日志，保留消息顺序。工具反馈用短摘要和折叠原文展示，草稿变更使用已记录的路径、字节数和首个变化行。
- 调用卡直接展示工具、命令、目标、状态及失败原因。参数与结果默认折叠，缺少结果时显示对应状态。模型正文及宿主收尾证据各自按存在性展示，默认折叠。日志默认折叠，清空后就地释放日志副本并保留业务区块。缺少的生成参数显示未记录。界面使用标题和字段标签。
- 详情按稳定请求地址读取。来源调用仅匹配同一 Writer 任务内严格早于当前轮且唯一的工具调用 ID，查到时可进入该轮详情。任务列表和来源链接使用直接目标导航，兼容首页绑定的同类型导航路径。提供下拉刷新，单页仅允许一项读取或清日志操作，失败保留已有内容。

## 接口与持久化

- UI/Settings 的 WriterRecordsControlling 返回专用详情 DTO，承载概览、已选请求、输入回退、来源请求和宿主收尾。WriterContainer 继续拥有业务投影，复用列表的轮次标题逻辑和通用 Prompt、工具证据类型。现有任务导出和 Assistant 接口保持各自契约。
- Storage/Database/WriterMessages 在现有表上补充详情序号和来源查询，从当前请求对应的日志投影可选模型参数。宿主收尾记录以所属模型调用 ID 保存到 runtime_results_json，修复独立随机 ID 无法命中持久化行的问题。读取收尾只选择当前调用已有的记录。无表结构变化，缺少历史收尾证据时省略相应项。
- 同步 UI/Settings、Agents/Writer、WriterMessages 和总体设计。覆盖同任务工具溯源、单轮收尾写入与重开读取、缺值及清日志保留，更新已有原生 UI 验收断言。运行 check.sh 与 build-ios.sh，分别记录原生及设备范围。
