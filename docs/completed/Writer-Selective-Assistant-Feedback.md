# Writer 精选事件进入 Assistant 语音与上下文

## 行为

Writer 继续在自身灵动岛及窗口展示普通步骤。认证跨角色回馈包括接纳、首次实际草稿改动、首次进入真实恢复重试或渲染检查发现问题、等待用户回答，以及已保存的成功、拒绝、失败或取消终态。每个委托的草稿和恢复提醒各一次，真实工具/生成结果先于对应事件。终态清理尚未播放的普通里程碑和过期追问。

Assistant 验证来源、委托、顺序和终态记录后更新委托视图。以简短事件文本复用既有合成和播放动作，无额外模型轮次。正式用户输入优先，通知与原回复共享单 worker 和播放链。通知队列上限八项，先舍弃较旧的普通里程碑，满后舍弃最旧的待播通知并保留事实，记录容量诊断。暂停不播放，停止或关闭会话清理相应队列。语音错误通过原 Assistant 输出错误路径报告，不回滚事件或 Writer 结果。

每个委托视图保留最近六条已接纳事实。随后真正的 Assistant 请求在原对话内读取最多两个最近委托的简短事实，附在当前状态数据中。消费证据仍由通信/上下文记录所有。Assistant 角色内存上下文随角色生命周期结束，数据库 schema 不变。

## 归属与接口

- `WriterWorkflow` 在真实写入和恢复检查点报告里程碑，`WriterAgent` 按委托去重后沿用 `task.progress`。已提交的终态继续使用 `writer.completion`。
- `AgentTasks` 定义事件和委托视图。`AgentChatWorker` 接收认证事实、调度播放，并把原对话的事件摘要附在下一次模型请求的状态中。独立语音通知与 Assistant 的前台任务控制可以并行。
- 现行技术说明由 Writer、Assistant、Chat 和 Communication 各目录维护，跨角色流程由总体技术设计维护。

## 验收

用现有 Writer Gateway/Assistant 夹具验证合成和播放、用户问题接续、恢复和草稿只提醒一次、重复终态不重播、后续上下文、普通进度保持本地、现有任务不被改变。运行 check.sh 与 build-ios.sh，分别记录替身音频和设备体验。
