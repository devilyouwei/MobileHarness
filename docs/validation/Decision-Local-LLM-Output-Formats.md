# 本地 Core AI LLM 的 Decision 输出格式对照

复用 2026-11-13 已固定的 100 条中英及混说场景。各模型使用自己的聊天模板、同一语义规则和输入，关闭可配置的思考。分别对比首位置三候选分数、贪心完整单词、贪心完整数字、通过模型原生聊天模板声明的 classify_input 调用。词和数字的候选独立比较，局部词片不能代表完整单词。输出缺失、越界、截断或结构错误分别记录，准确率以全部样例为分母。Tool Call 只解析动作，不执行业务。

先用已有 Core AI 制品建立横向基线，再加入不超过 2B 的千问制品。每个配置单独预热，记录格式合规率、混淆矩阵、危险误判和 Mac 热态延迟。冻结同一协议后再看片，不使用这 100 条训练或校准。实验脚本在 Pro 独立目录，最终原始数据归 experiments/decision/results，沿用历史文件命名。此前 [Mac 对照](Decision-Model-Mac-Comparison.md) 保留。

## 实施与计分

在 Apple M5、16 GiB、macOS 27.2.1（26B131）上运行实际 Core AI 图。样例分布为打断 24、丢弃 26、入队 50。固定英文规则和 JSON 输入状态，保留每条原始中英文转写。贪心解码在结束 token 停止，词和数字最多生成 10 token，工具最多 64 token。去掉首尾空白后，普通生成必须精确匹配标签，工具生成必须是模型聊天模板定义的一个完整调用，函数为 classify_input 且 action 为合法枚举。无效结果计入总分分母，未正确打断的无效结果计入漏打断。工具声明通过模型原生模板渲染，提示词要求调用一次，未添加语法约束和重试。

词、数字两套提示词都分别跑候选打分和完整生成。打分只取合法候选的首位置 logits，校验三个标签的 token ID 在实际提示词末尾稳定且各自独立。MiniCPM5 的三个完整动作词无法全部用一个 token 表示，该组合跳过。数值分数只用于三选一，无效完整输出单独计数。

每配置预热三条，逐请求重置。热态包含聊天模板渲染、编码、图推理和读出，排除模型装载、一次性前缀及宿主对结果的文本解析。Qwen3.5 2B 的单 token 图使用共同系统前缀状态，其他制品重置到零。计时以逐条墙钟时间计算，p95 取最近秩。固定 100 条与此前实验一致，包含已知重合样例。此轮改了提示词表达与输出方式，因此跨轮差异同时受提示词变化影响。

新增制品是 Qwen3 1.7B 的 INT8 图和 Qwen3.5 2B 的文本 INT8 图。两者分片下载后以发布方 SHA-256 校验。模型名和参数档位依据上游发布，2B 实验只加载文本图。 [Qwen3 1.7B](https://huggingface.co/Qwen/Qwen3-1.7B) · [1.7B 制品](https://huggingface.co/kevinqz/Qwen3-1.7B-CoreAI) · [Qwen3.5 2B](https://huggingface.co/Qwen/Qwen3.5-2B) · [2B 制品](https://huggingface.co/mlboydaisuke/qwen3.5-2B-CoreAI)

- Qwen2.5 1.54B 的单词打分 62 条正确且全量在 500 ms 内，是本轮预算内总分最高组合。24 条应打断中命中 12 条，26 条应丢弃中命中 0 条，50 条应入队全部命中。中文历史组 27/48，应用探测 6/8，诊断 15/20，英文 6/12，混说 8/12。它适合作为后续实验基线，漏打断率仍高。
- 四个千问制品在单词打分和生成单词之间的逐条结果一致。Qwen2.5 单词打分比完整生成的 p95 少约 17 ms。数字打分能提供一个合法标签，但 Qwen3 0.6B 的自由生成 100 条均未通过严格格式，它经常输出 `3 means enqueue.`。MiniCPM5 数字输入输出条件有 68 条误丢弃。
- Qwen3 1.7B 的 Tool Call 有 68 条合规，41 条正确，其中 1 条调用超过 500 ms。常见错误是把动作当函数名。Qwen2.5 的工具条件产生裸动作词，100 条均无合规调用。2B 的工具合规 100/100，正确 42/100，误丢弃 51 条，全部超过 500 ms。2B 工具模板实际输入为 452–469 token，最初 512 token 容量无法预留 64 token 生成，本组使用 1024 token 缓存容量复测。在单词打分的 5 条缓存抽查中，完整前缀重跑与缓存复用分数完全一致。
- 2B 各组合均全量超预算。总分最高的数字方式达到 65/100，其中误丢弃 24 条、漏打断 16 条。延迟与特定的单 token 图和运行方式相关，不能据此推定其他 2B 制品的时延。

## 后续设计

先保留单步候选打分作为主要对照。对单 token 标签直接比较分数可以省掉生成收尾和解析成本，但这些分数目前未校准成业务置信度。近期开启独立的训练、校准与盲测集，重点增加短语肯定回答与无意义附和、否定或延迟的“停”、ASR 残句，以及同一转写在不同上下文应采取不同动作的配对。用分开校准的打断和丢弃阈值评估保守入队策略，记录覆盖率与危险误判。再与业务监督微调后的相同模型或分类头比较，复测量化后的 Core AI 图和 iPhone 端到端时延。完整单词生成可保留作诊断，Tool Call 可保留作协议对照。
