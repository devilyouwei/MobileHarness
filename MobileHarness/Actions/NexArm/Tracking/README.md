# NexArm/Tracking — 业务能力与执行

## 职责与关系

跟踪只保留最新目标，命令提案与实际接纳分开。每次写入核对输入新鲜度、连接代际与资源许可；退出关闭并加入原生会话清理，不发额外运动包。根控制服务拥有跟踪任务，规划状态不创建后台工作。

本目录由所属域目录绑定，接受标准 FunctionInput；调用权限、通用调度与资源仲裁由上游 Gateway 保持。下游只消费注入的基础能力。

seed 只初始化规划参考；后续以最后接纳位置目标估计行程，不作为实测到位。新目标覆盖未接纳提案，只有接纳才能提交逻辑目标、前瞻位置与采样时间；旧提案迟到不能提交新状态，相同目标仅在成功接纳前重试。3 count 门槛减少细小变化的等待，重复位置不发包。前瞻最多一个已接纳目标步幅，采样间隔超过 0.4 秒不外推；运行速度按目标差/实际间隔计算并受 SDK 连续位置控制上限约束，首次使用名义 0.2 秒。首次位置包包含电机2/3水平准备，后续只含1/4；每个目标及前瞻均受 PlatformKit 位置范围约束。位置动作速度参数不改变舵机模式。无扭矩、模式或持续速度寄存器写入；固件位置模式是运行前提。

设备限制直接读取 PlatformKit 的 `NexArmDeviceLimits`，不经手动规划器间接拥有。根 worker 每 50 ms 检查最新目标，静止 300 ms 后结束；发送因背压返回 false 时不推进已接纳历史，不补发中间目标。
