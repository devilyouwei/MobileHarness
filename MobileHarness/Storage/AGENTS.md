# Storage 开发规范

适用于本目录及其子目录。先读[仓库规则](../../AGENTS.md)、[模块设计](README.md)和受影响的存储契约。

## 开发边界

- 保持基础模块独立。使用 Storage 公开 DTO 和注入端口，禁止导入其他项目模块、复制其私有对象、依赖当前界面或解释 Agent 的意图。
- 优先修改数据所有者的表、仓库或文件操作。跨表写入用同一个事务，跨文件与数据库写入沿用已有补偿和恢复契约。提交失败、版本冲突或部分效果必须可观察，禁止返回假成功。
- 遵循现有 schema 版本契约。改变 schema 或持久语义时核对旧库打开、失败恢复和数据保留预期。禁止把持久数据的销毁作为开发便捷路径。
- 文件名与目录在拥有的根内校验，媒体、临时产物和数据库记录各有生命周期。禁止在提交中带入真实用户文件、凭据和本地数据库。诊断 State 读取现有事实，禁止借机打开数据库或创建文件夹。
