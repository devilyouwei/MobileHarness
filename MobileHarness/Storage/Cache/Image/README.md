# Session image cache

Image is the StorageCache image capability alongside Audio. PreviewImageCache owns one reopenable session, ordered immutable original bytes, derived analysis bytes, metadata and consumer-written pending/ignored/saved markers. CacheContainer owns its single cameraImages handle and terminal shutdown. It imports only Foundation, Synchronization and StorageCore; no image decoding, model selection, UI or Camera execution is performed here.

open(scope) admits one nonempty scope only when inactive. reserve(id) admits one bounded capture without modifying existing entries. publish validates nonempty bytes and dimensions, appends the image and atomically retires the oldest image if the20-entry bound is exceeded; the retired ID is returned to the caller. Failure/cancel before publish leaves the entire existing array intact. IDs are supplied by the consumer and never renumbered. All accesses are serialized by one mutex; immutable Data uses value/COW semantics.

The independent encoded-byte budget is112MiB: at most20 originals of4MiB, at most1MiB analysis per retained image, and one4MiB capture reservation. It does not consume the general BufferCache's64MiB budget. reserve includes provisional bytes in capacity admission. No fallback writes to disk. Runtime reporting includes camera image count and retained bytes; UI decode and in-flight consumers own their separate bounded references.

mark changes metadata only. read returns the stored original; analysis is removed on selection release or FIFO eviction. endSession releases all originals, analysis and reservation and permits another open. close additionally seals the handle permanently, including root shutdown. Reads/admission after closure or missing identities fail explicitly. Camera controls session timing and applies save/ignore semantics; Storage only stores supplied facts.
